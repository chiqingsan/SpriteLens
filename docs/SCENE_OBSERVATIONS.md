# C02 场景实体观察快照

状态：当前观察版规格，部分协议与现场生命周期待验收。读者：维护者与后续 C03 实现者。用途：维护输入证据、所有权、只读契约和失败边界；任务状态统一见 [路线图](ROADMAP.md)。

## 实现边界

2026-10-24 中途恢复规则更新：连接身份必须由监控/账号路由确认，密钥本身不作为账号归属。确认身份后，首次收到的 `0x0133 c2s.field17` 可建立场景，field2 提供客户端目标坐标；之后场景号变化清空旧周期。即使尚未取得场景号，也接纳本连接新下发的 `0x0413/0x0414` 进入/离开实体，等待新位置后绘制雷达，不要求完整 `0x014A`，不补回缓存实体。无身份、其它会话及战斗中的实体仍不接纳。

位置更新支持动作 12 `server_move` 的 actor_id、时间列表 3 和位置列表 4；按接收时间对齐路径首点，按路径时间差进行二维线性插值。插值是估算位置，并非每一时刻服务器确认位置；不把路径末点立即当作当前位置。动作 13 `interrupt_server_move.3.1` 和 222 `set_npc_pos.2` 使用直接下发位置并取消旧路径。进入覆盖、离开、切场景和战斗清空相应路径；未知实体的移动不能凭空创建测量实体。无效路径计入未解析，不猜字段。原始坐标显示/删除阈值仍是产品策略，尚非实测 AOI 半径。

离线验证：今天已有事件记录的最近约 100 MB，以多个切点从空仓库重放实际 `SceneRepository`，不加载 checkpoint，测试替身仅注入“上游已确认连接身份”的契约。各切点均从后续数据恢复实体、场景 103 和玩家参考位置，未要求完整进场快照；最终列表受距离清理策略影响，不等于全场景集合。该验证使用已解码字段树，不能替代原始字节重新解密、实时游戏位置对照或无丢包证明。回归覆盖无身份拒绝、外会话隔离、中途建系、路径插值、中断/直接设点及原有场景/战斗生命周期。

独立 `domain/scene.py` 解析当前解码字段树，`SceneRepository` 单锁拥有账号、会话、场景和实体的内存状态。组合根接入现有 MonitorService；使用同一个实时/回放管线，不建立第二个抓包源，不写业务 SQLite；正常停止时仅把场景上下文按账号与抓包流异步写入 version=2 JSON，中途增量接入也可保存；不写实体和坐标，旧 version=1 派生缓存弃用。重启只在同一流获监控确认后恢复上下文，等待新实体与位置。本模块不计算米制距离或方向；只在有服务器确认的位置时才按可配置原始坐标阈值清理远处实体（默认 15,000），客户端移动目标不参与裁剪；页面见 [C03 规格](NEARBY_OBSERVATIONS.md)。

只收录带身高、体重或音量字段的 NPC 观察。其它 NPC 和玩家不当作野外精灵；目前不保证覆盖缺少这些字段的特殊形态。字段缺失使用 null，显式零值保留；actor ID 和 uid 在 JSON 中转字符串。缺失位置分量也保留 null，不拼出假坐标。快照由 frozen dataclass 和 tuple 组成，后续更新不会修改已经返回的快照。

## 协议证据与待验收项

- 本机 2026-10-22/23 的现有事件日志中，335 个场景 NPC 含身高字段；`0x014A.field7[].11.1` 是 NPC 基础字段，`.11.3` 是配置与测量字段。ID 为基础字段 2，等级为 11，位置为 8.1；配置 ID 为配置字段 1，身高/体重为 11/12，音量为 31，mutation 为 14，glass 为 30.1/2。测量字段的单位/奖牌语义不在本轮裁定。
- 当前日志确认 `0x0414.field1[]` 是动作包装；`0x0413` 要先进入顶层 field1，再取内部 field1[]，不能直接照抄外部工具统一分支。动作 1 的 field1[] 是进入实体，动作 2 的 field1 是离开 ID（支持普通 varint 与 packed bytes）。不支持的动作累计 `unresolved_updates`，不能报告已同步全部状态。
- `0x0152` 的场景/资源/实例为 2/3/4；非零返回码不改变现有观察。`0x015C` 的对应字段为 11/12/13，位置为 14.1；每次传送均开始新观察周期，即使场景编号不变。普通场景进入在场景、资源或实例变化时清空，不用单一地图编号判定归属。
- `0x0133 c2s` 的 field2 为移动目标坐标、field17 为场景；身份确认后可建立场景，场景号变化时清空旧周期，来源明确为 `client_target`。传送位置来源为 `teleport`。客户端目标不等于服务器确认位置，坐标单位仍为 `unverified`。
- 战斗进入 4886 时清空实体和位置并标记 `battle_unverified`，期间不收 AOI/移动观察；结束 4908/4909 时**不恢复战前雷达快照**（用户决策 2026-10-24：选项 A「清空 + 等游戏重新下发实体再重建」），保持空态与 `awaiting_scene`，等新观察周期的有效增量或完整快照原位重建；场景变化不会恢复旧场景。当前日志的 17 对进入/正常结束消息确认战斗编号路径为 `4886.6.1` / `4908.1.19`，有已知编号时拒绝不匹配或缺编号的正常结束消息，并累计 `unresolved_updates`。未观察到进入编号时仍保守清空；4909 强制结束尚无现场样本，仍只作失效信号。场景/账号/会话重置一并清除战斗编号，不实现战斗复盘。
- 17 次正常战斗结束后首先观察到的是 14 次 `0x0414` 和 3 次 `0x0413`，没有先重发进场景应答。真实回放（2026-10-24，11 个战斗窗口）确认结束后 120 秒内服务器会重新下发 0–142 个实体，因此按用户决策采用「清空 + 等待重发」：结束后保留场景上下文，同场景保持空态，收到有效增量或完整快照后原位重建，仍不要求重新登录或传送。新位置需重新观察，`complete=false` 始终保留。已修复接收新实体后仍停在 `awaiting_scene` 的状态错误。

现有 33,667 条本机解码事件可顺序处理，观察到 905 次实体数量增加、786 次减少，最多 78 个实体。此为已解码事件核对，日志没有完整的流关闭事件。另对一份 2026-10-22 的本机字节录制运行直接管线和 ReplaySource：9,155 段流，成功解密 9,397 条事件（其中 5,083 条场景事件），最多 57 个实体；去除处理时刻后，逐事件业务观察序列一致，无缺密钥。该验证不等于现场交互验收。只提交统计与合成测试，不复制本机日志、账号、密钥或录制。

## 生命周期与失败分支

- 未识别本次身份时不收录实体；身份已确认但尚无场景号时可接纳本连接的新实体增量，不借用背包离线身份。身份归属沿用 AccountTracker；切号或确认新会话时清空，旧会话的晚到身份/实体被拒绝。
- 最多记住 256 个退役会话，对齐管线会话上限。流关闭或新 SYN 释放相应隔离记录，允许同一个连接标识后续被新连接使用；活动会话失效后必须重新确认身份。
- 采集 start 在启动新 source 前清空观察；成功 stop 确认投递/嗅探退出后先保存当前场景上下文，再清空内存观察。停止失败/超时不冒充已停止，不让新一代 source 越过现有停止所有权。关闭/SYN/ACK 新握手/空闲回收/LRU 淘汰均通过 session close listener 使活动观察和对应基线失效。
- 历史账号选择只有在全部历史域读取并应用成功后才清空场景观察，保留所选 uid 并标 `historical_account`，没有历史附近缓存。历史读取失败不清当前观察；切号命令仍受采集命令锁保护。
- 最多保存 4096 个实体；满时拒收新 ID 并增加 `rejected_actors`，不静默淘汰。无法定位的测量实体和坏离开 ID 计入拒收/未知计数。未知增量不猜语义，也不把某次 AOI 当作完整世界仓库。

## 接口与验证

`GET /api/nearby` 沿用现有本机 token 鉴权和受控后台 runner，返回 uid/version/phase、scene_id/resource_id/instance_id、player_position/position_source、updated_at、actors、unresolved_updates/rejected_actors、mapping_available。该 GET 禁用 HTTP 缓存，缺失映射不补猜物种。所有快照固定 `complete=false`、`source=observed_partial`、`coordinate_unit=unverified`；不输出包含本机地址的会话字符串。未装配该域的测试/精简实例返回 503。

现有 WS `state.nearby` 含 uid/version/observation_id/phase，页面按版本拉取列表；不在 WS 复制整份实体数组。C03 需按响应 uid/version 和页面代次处理晚到请求。

79 项相关 Python 回归通过（其中 9 项 C02 回归）。命令：`python -B -m unittest tests.test_scene tests.test_monitor_service tests.test_recording tests.test_account_selection tests.test_runtime_repair tests.test_view_models tests.test_web_server -q`。

合成回归覆盖字段缺失/零值/负数、大 ID、进入/离开及不同包装、未知动作、实体数量上限、场景实例与同地图传送、切号与旧会话、方向过滤、战斗失效、断流与停止、真实组合根装配/关闭、接口鉴权，以及合成加密分段流录制/回放一致性。现场进出战斗、多账号抓包、丢包恢复及当前游戏距离单位仍需实际证据；按用户后续要求以解包实现适配先行，C03 已交付标明不完整的观察列表；这些缺口继续保留，不升级为完整场景或坐标契约。

2026-10-23 战斗恢复复核：只读顺序处理本机 10 月 10–23 日现存事件日志，17 对正常战斗编号全部匹配；修复前可复现 8 次已有实体但仍等待场景，修复后观察到 10 次战后重新出现实体，状态均为 observing。两项新增合成回归覆盖编号不匹配/缺失、战中屏蔽、正常结束后增量恢复与场景切换清除编号。该证据来自已有日志，不能替代当前版本现场多账号、强制结束、丢包恢复及坐标校准。2026-10-24 起按用户决策不再保留「战后恢复战前快照」实现（死状态 `_battle_backup` 已删除），只保留「清空 + 等服务器重新下发后重建」路径；本文历史段落中的「恢复战前快照」描述均为旧版设计记录。

握手边界补充：中途接入只观察到 ACK 时也使旧场景失效，避免同连接标识的新密钥握手继续沿用旧实体；已补合成 ACK 回归。场景、监听、录制及运行时修复共 37 项定向回归通过。

C03 接口补充：`observation_id` 随清空周期增长（包括同场景传送和战斗边界），用于页面立即丢弃旧周期实体。每个 actor 增补精确 NPC 映射得到的 base_id/name/icon_url/type_names；缺映射时保留未知，不把配置 ID 直接当物种 ID。
