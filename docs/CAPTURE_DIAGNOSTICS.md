# C01 采集与连接设置

状态：当前功能规格。读者：用户、维护者与开发者。用途：维护向导操作、诊断语义与接口边界；持续任务状态和验证结果统一见 [路线图](ROADMAP.md#c-系列资源分析后的功能迭代2026-10-23)。

## 双开会话诊断（M01）

会话表逐连接显示账号/UID、最近数据时间、已有密钥、数据帧与解析成功/失败数；等待密钥、等待身份、解析失败、正常和已停止分别显示。单个连接成功不能代表双开全部成功。账号浮层可在采集中“切换查看”，后台继续按连接归属更新各自账号，不操作游戏；未确认身份的连接不写入业务仓库。

## 使用

设置页的“采集与连接”以一个状态区和连续设置行组织，不再把诊断做成四张独立卡片。顶部统一展示当前需要做什么、采集启停和环境/采集/密钥状态；正常时不显示驱动路径、安装说明或下载链接。“查看诊断”位于面板的连接状态栏，一次展开原始依据、重检、手动密钥、会话表和累计统计，环境异常、安装中及命令失败自动展开。

连接面板内直接放置启动选项和录制区：打开即采集、游戏启动跟随以可独立勾选的选项呈现；自动录制、当前状态和录制启停放在同一个录制区。桌面并排，空间不足时上下排列，不再拆成四条设置行。面板下方仅保留网卡设置。网卡列表通过“刷新”枚举，选择后下次启动采集生效；不确定时使用默认路由。主端口和附加端口只读显示在选择框下方；完整已选网卡名在该处换行，选择框本身保持单行。

设置开关由服务返回值确认，保存失败不留下浏览器先行切换的勾选状态。游戏启动跟随沿用已有计划任务命令；“启动时自动录制”在采集中修改会立即启停录制，当前录制按钮在采集未启动时禁用。未新增命令、接口或持久化配置。

“刷新状态”读取现有快照；“重新检测环境”实际运行 Npcap/RSC 探测。缺驱动时可启动已有官方安装流程；安装时保留 WinPcap API-compatible Mode，安装器退出后自动检测。RSC 处理沿用已有明确点击入口。

RSC 只判定实际抓包的那块网卡：优先用「抓包网卡」中已保存的选择，未选择时取默认路由网卡；其它网卡（Hyper-V 虚拟交换机、WSL、蓝牙等默认开启 RSC 的适配器）不参与判定，因此装过虚拟化的机器不会被与游戏流量无关的虚拟网卡误报为「环境待处理」。只有该网卡 `IPv4Enabled` 为真才告警并给出「禁用 RSC」入口；查不到该网卡的 RSC 项时如实显示“未能读取”，既不宣称环境正常也不谎称 RSC 已关闭。切换网卡后需点「重新检测环境」刷新结论。

无数据时先检查网卡，并在采集启动后重新登录游戏；这不是网卡/端口错误的确定证据。已有密钥、成功解密及累计警告分别展示；累计成功不代表当前连接健康，也不代表业务数据完整。停止采集不会把旧累计计数伪装成本次成功。高级诊断保留手动密钥、会话和原始计数。

## 契约与所有权

- `GET /api/capture` 和 WS `state.capture` 增补 `port`、`diagnostics`，保留原有消费者字段。诊断项字段为 `id/title/status/message/actions`；固定检查为 `environment/network/capture/decrypt`，有警告时附加 `warnings`。
- 状态为 `ok/error/warning/info/idle/waiting`；动作标识为 `recheck/install/rsc/ifaces/start/stop/advanced`，Vue 映射到现有命令和高级诊断入口，不执行服务端下发的代码或 URL。
- `POST /api/capture/environment` 沿用本地 token 鉴权及受控后台 runner；成功返回完整采集载荷，重复探测返回 409，探测失败返回 500。检测进行中由 `environment.checking` 标记；失败保留旧报告并在 `environment.refresh_error` 和诊断项中标明；后续成功清除错误。
- 网卡枚举失败返回 500，不把失败显示为成功的空网卡列表。选择保存失败沿用现有错误契约：运行态选择可能已生效，但持久化失败。
- Python `capture_diagnostics` 只做快照判断，无 IO；CaptureViewModel 拥有系统探测与互斥。Vue 独占整个采集分组的 DOM、设置控件与局部请求状态；TypeScript 校验现有 API 中的端口、采集/密钥/录制、启动偏好和跟随字段。原生壳只提供请求、状态传递和顶栏状态；高级诊断已一并由 Vue 承接；不新增连接或轮询。
- 页面请求期间禁用重复操作；卸载后晚到的响应不发布到壳或新组件。系统探测失败会向调用方传播，后台启动探测也保留错误供界面展示。

## 验收与维护边界

运行相关 Python 回归、组件生命周期回归与 Vue 构建。真实渲染应覆盖正常/极限数据、长网卡名及连续错误文本、安装中/加载中/空态/失败、窄窗、高缩放和字体回退；发现布局问题需修正后复验。

本功能不改协议、数据库、录制和回放；附近精灵和后续功能不在 C01 范围。真实驱动、安装/UAC、游戏流量及打包态必须单列实机证据，浏览器和合成快照不能替代。

## 游戏跟随的系统操作等待与窗口策略

启用跟随只需注册计划任务，关闭只需查询/移除任务，都不再改动进程创建审计策略；HTTP 已使用受控后台 runner，但系统命令完成前不能确认开关成功。界面在选项旁显示正在启用/关闭的等待说明，完成或失败后清除，失败保留已确认状态。直接执行的 schtasks 查询/创建/删除命令在 Windows 使用 CREATE_NO_WINDOW（输出按 mbcs 解码，避免中文环境下把「拒绝访问」解成乱码后漏判提权分支）；仅在覆盖旧版本遗留的提权任务、系统返回权限不足时才弹出一次 UAC。

19 项游戏自动监听 Python 回归通过（任务 XML 为登录触发器、无 4688/审计策略、仅在权限不足时提权；窗口监听器的事件过滤与重新武装；后台等待/占位/会话退出分支），7 项组件回归与构建通过；本机只读任务查询正常，同标志测试子进程 GetConsoleWindow 为 0。实机复验 `SetWinEventHook` 零权限命中窗口创建事件（125ms）、空闲 30s 不误触发、`wait_for_process_exit` 走进程句柄而非轮询、任务替换后进程创建频次归零、空闲不持锁、游戏启动/退出两轮抢锁与释放正常。Edge/Playwright 验证启用/关闭等待提示、成功后确认和失败恢复，无脚本异常。打包 exe 下的实际窗口表现仍需实机复验。

## 诊断内联整合

“查看/收起诊断”位于连接状态栏右侧，展开内容直接包含高级诊断，不再需要跳转或第二次折叠。手动密钥沿用 `/api/capture/key`，成功后清空输入并刷新采集快照；失败保留输入、显示错误，不报告成功。会话和累计统计读取同一采集载荷，原生设置页的旧高级诊断 DOM、渲染与事件绑定已删除。会话表有明确的 240px 纵向滚动上限，长会话名换行；窄窗为计数列保留更多宽度。

9 项组件回归与构建通过。Edge/Playwright 验证一次展开即能应用合成密钥、显示会话/空态并刷新状态，收起隐藏完整诊断区；正常与 256 个超长会话、长日志名、连续错误覆盖 1440×1000、640×360、390×844、150%/200% 缩放及字体回退，未发现横向溢出或脚本异常。
