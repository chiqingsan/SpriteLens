# C01 采集向导与健康诊断

状态：当前功能规格。读者：用户、维护者与开发者。用途：维护向导操作、诊断语义与接口边界；持续任务状态和验证结果统一见 [路线图](ROADMAP.md#c-系列资源分析后的功能迭代2026-10-23)。

## 使用

进入设置页的采集向导，按环境、网卡与端口、采集、解密的顺序检查。网卡列表通过“刷新网卡”枚举，选择后下次启动采集生效；不确定时使用默认路由。主端口和附加端口只读展示。选择框为原生单行控件，完整已选网卡名在检查说明中换行展示。

“刷新状态”读取现有快照；“重新检测环境”实际运行 Npcap/RSC 探测。缺驱动时可启动已有官方安装流程；安装时保留 WinPcap API-compatible Mode，安装器退出后自动检测。RSC 处理沿用已有明确点击入口。

无数据时先检查网卡，并在采集启动后重新登录游戏；这不是网卡/端口错误的确定证据。已有密钥、成功解密及累计警告分别展示；累计成功不代表当前连接健康，也不代表业务数据完整。停止采集不会把旧累计计数伪装成本次成功。高级诊断保留手动密钥、会话和原始计数。

## 契约与所有权

- `GET /api/capture` 和 WS `state.capture` 增补 `port`、`diagnostics`，保留原有消费者字段。诊断项字段为 `id/title/status/message/actions`；固定检查为 `environment/network/capture/decrypt`，有警告时附加 `warnings`。
- 状态为 `ok/error/warning/info/idle/waiting`；动作标识为 `recheck/install/rsc/ifaces/start/stop/advanced`，Vue 映射到现有命令和高级诊断入口，不执行服务端下发的代码或 URL。
- `POST /api/capture/environment` 沿用本地 token 鉴权及受控后台 runner；成功返回完整采集载荷，重复探测返回 409，探测失败返回 500。检测进行中由 `environment.checking` 标记；失败保留旧报告并在 `environment.refresh_error` 和诊断项中标明；后续成功清除错误。
- 网卡枚举失败返回 500，不把失败显示为成功的空网卡列表。选择保存失败沿用现有错误契约：运行态选择可能已生效，但持久化失败。
- Python `capture_diagnostics` 只做快照判断，无 IO；CaptureViewModel 拥有系统探测与互斥。Vue 独占向导 DOM 和局部请求状态，壳只提供请求、状态传递和高级诊断跳转；不新增连接或轮询。
- 页面请求期间禁用重复操作；卸载后晚到的响应不发布到壳或新组件。系统探测失败会向调用方传播，后台启动探测也保留错误供界面展示。

## 验收与维护边界

运行相关 Python 回归、组件生命周期回归与 Vue 构建。真实渲染应覆盖正常/极限数据、长网卡名及连续错误文本、安装中/加载中/空态/失败、窄窗、高缩放和字体回退；发现布局问题需修正后复验。

本功能不改协议、数据库、录制和回放；附近精灵和后续功能不在 C01 范围。真实驱动、安装/UAC、游戏流量及打包态必须单列实机证据，浏览器和合成快照不能替代。
