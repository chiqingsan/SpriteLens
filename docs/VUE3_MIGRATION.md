# Vue 3 前端演进决策

状态：当前前端技术方向与过渡边界，2026-10-22 更新。读者：实现者、维护者与架构复核者。
用途：固定技术选择和迁移方法；当前页面归属见 [AI_CONTEXT](AI_CONTEXT.md)，持续任务状态见 [ROADMAP](ROADMAP.md)。
已迁页面各自通过桥接挂载 Vue；原生壳仍拥有导航、账号上下文、UI 偏好和唯一 WebSocket。
构建命令见 [前端开发](FRONTEND_DEVELOPMENT.md)，开发约束见 [DEVELOPMENT_GUIDE](DEVELOPMENT_GUIDE.md)。

## 1. 技术选择

后端保留 Python + aiohttp + SQLite，桌面壳保留 pywebview + 系统 WebView2。
前端采用 **Vue 3 + TypeScript strict + Vite**，使用单文件组件与 Composition API（script setup）。
新增前端工程放 `frontend/`，源码、测试和锁文件独立管理；已同步代码地图。

| 能力 | 选择 / 使用边界 |
|---|---|
| 开发工具 | Node.js 24 LTS + npm，提交 package-lock.json；CI/发布用 npm ci；首次落地固定已验证工具版本 |
| 导航 | 当前主导航由原生壳管理；蛋图鉴独立挂载点使用单路由 memory history。全壳迁移时再统一 Vue Router；token fragment 不作路由 |
| 共享状态 | 当前账号、采集状态和 UI 偏好仍由原生壳持有；页面状态在 composable。Pinia 仅在蛋图鉴挂载点安装，没有业务 store；统一共享状态属于后续全壳任务 |
| 请求 | 一个 fetch 客户端，集中鉴权、取消和可读错误；REST DTO 与 WS 类型集中定义，响应按实际需要做运行时校验 |
| 测试 | Vitest 保留请求/状态/保存失败等必要回归；简单展示与布局用必要目视检查 |
| 代码检查 | 构建内执行 vue-tsc；已取消 ESLint 和整套浏览器测试，不再重复类型检查 |
| 视觉与资源 | 复用 UI_GUIDE 的 CSS tokens、主题、Tabler sprite 与现有图片映射；初期使用项目自身基础组件，组件库按真实需求再评估 |

初期不增加 SSR、Nuxt、Electron、Tailwind、自动导入插件或第二套网络客户端。
前端不承接协议解析、持久化和配窝计算等业务规则；组件只处理展示、交互与用例调用。
新库必须说明解决哪个问题、运行体积、许可证和验收方式，不因模板默认包含就引入。

## 2. 工程与发布边界

`frontend/src` 按 pages、components、composables、stores、api、types 的实际职责组织，避免空目录和通用万能组件。
composable 不绕过 API 客户端，各页不各建 WS；应用只持有一条连接及其重连定时器，卸载/关闭时清理。
全壳迁移后由 Pinia 保存后端快照的展示状态；当前不为此提前建立第二份状态。Python 仓库始终是业务数据权威来源。

迁移期只在明确的页面根节点挂 Vue；该 DOM 子树由 Vue 独占。旧模块不得再操作其中节点，
Vue 不直接读写旧 app.js 私有状态；通过有类型的桥接接口接收主题、请求和导航。
桥接接口临时存在，最后一页迁完即删除，不能成为长期平行状态系统。

Vite 产物先落在 `frontend/dist` 暂存目录；只允许发布步骤将通过验证的产物合入运行静态目录。
首次工程任务必须列明生成文件的所有权；构建不得 emptyOutDir 清空现有 web/static 或图片。
保留 `/static/` 媒体 URL；通过构建 manifest 检查入口、哈希 JS/CSS、懒加载 chunk 和图片引用。
发布只收运行时产物，不打包 node_modules、Node.js、Vite、开发测试或 source map。

开发页从本地 aiohttp 获取 token 并同源运行；V01 先采用 build/watch 输出 + 浏览器刷新，
避免为了 HMR 扩大服务绑定、关闭 token 鉴权或放开跨域。后续如需 HMR 单独设计开发隔离。
缺构建产物、产物与源不匹配或引用缺失时发布失败；源码运行/合成 demo 也要有明确的构建前置。
体积与冷启动用同一份资源、依赖和压缩设置前后对照；之前的 80–100 MiB 是资源规模估算，不能作为实测验收值。

## 3. 接口与状态约定

- TypeScript 类型不检查网络 JSON。迁移接口需明确缺失/null/未知字段、错误结果和实际运行校验，
  不用 `as` 断言把任意响应当成正确 DTO；初期只定义被迁页面需要的契约，数量增长后再评估类型生成。
- 列表与状态响应明确 uid/version；历史、不完整、未知与实时分别保留。请求记录账号代次与序号，
  切号/新请求使旧结果失效；取消请求与校验结果同时使用，避免取消晚到仍提交旧响应。
- **64 位标识符按十进制字符串传输**，不能先 JSON.parse 为 number 再转字符串。
  按字段协议确认 actor_id/guid 等 uint64/int64；已确认 uint32 且范围安全的 gid/目录 ID 继续保留数值，
  数值指标仍为 number。载荷转换、旧消费者和测试一起迁移；原字段类型变化时明确兼容，不做全局数字转换。
- Python 保持既有 dataclass/domain，HTTP 转换集中在载荷边界；后端契约测试与 TS DTO 同步。
  错误在客户端集中归一，初期兼容既有 error/message；规范错误格式时同时更新 HTTP 测试和调用方。
- WS 是变化提示；页面按版本按需刷新，重复版本不重复请求。重连重新同步需要的快照，
  事件订阅、重连与定时器只有一个所有者，不能每个页面重复启动。

64 位风险已有代码证据：demo 的家园 actor_id `9518406239959121930` / `9518406239959121931`
在 Python 中不同，但转换为双精度数后相等；home_payload 已按字符串传输并有 JSON→JS 回归。
F00 已补 JSON→JS 端到端区分用例。是否扩大到其它 ID 根据协议和样本确认。

## 4. 迁移顺序与验收

1. **V01 工程底座**：锁版本、类型/构建入口及必要回归、明确生成文件边界、同源鉴权和发布 manifest 检查。
   现有界面持续可启动，clean build 不删资源；构建产物可在离线本地服务与 WebView2 加载。
2. **V02 蛋图鉴首个 Vue 页面**：迁组件、筛选、详情和请求生命周期，复用当前视觉与数据。
   验收筛选、详情/键盘/焦点、主题、切页返回、乱序响应、重复挂载/卸载；旧页实现随切换退出该入口。
3. **F03 宠物页**：在相关账号/快照契约落实后分切片迁移请求/筛选、两视图与箱位、详情/快捷条件。
   各切片行为验收，禁止让两个实现共同写同一块 DOM 或维护同一份页面状态。
4. **F04 其它页面与应用壳**：按功能依赖迁图鉴、蛋仓、家园、采集与事件；
   收口导航/WS/偏好后删除临时桥接、旧入口与失去调用方的脚本，扫描引用并做发布验收。
   图鉴与炫彩色卡已迁入（`pages/HandbookPage.vue`、`pages/ColorsPage.vue` 及各自 bridge；对应旧渲染函数已从 app.js 删除）；
   余下页面与壳收口仍未开始。

基础类型与工程可先建设，不必等待所有无关后端任务；账号相关页必须满足所需稳定性与快照条件。
不同时重新设计视觉、修改协议与换前端，迁移以原行为可验证为界。

每次按 [开发指南的测试取舍](DEVELOPMENT_GUIDE.md#测试取舍) 选择验证；迁移切片关注接口契约、类型/构建与关键交互，
不要求简单展示改动新增组件测试，也不重复在各层测试同一行为。
WebView2 与 exe smoke/GUI 是最终发布验收；Chromium 测试不能自动代表桌面壳已验证。
rollback 保留在 Git 提交边界，失败回退整个相关切片；不建立永久旧/新 UI 切换选项。
