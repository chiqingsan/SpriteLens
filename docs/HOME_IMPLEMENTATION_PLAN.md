## 1. 目标与证据

以项目自身的被动采集数据实现家园居民卡片、窝位、场景配对、后代预测和位置地图，沿用现有 Vue、Python、主题与资源体系。

已确认的输入事实：

- 蛋神采集运行时，`/api/home/info` 读取本地 `home-capture:<gameId>` 缓存；结果字段名 `remote` 不代表必定来自网络。停止采集后的在线家园查询是另一条可选路径。
- `0x014A` 是通用场景进入应答；顶层 `field22=home_info`，重复 `field7=other_actors`。家园主人取 `home_info.field2`，房间等级取 `home_info.field5`。
- `other_actors` 的第一个 actor 的 `field1=actor_detail_type`。旧路径把其值 10 当房间等级，再误读 NPC 为居民；这一分支没有“旧版家园协议”的证据。
- 本机已有三份目标家园字段树可提取：房间等级 5、11 个居民、81 件家具，其中 10 个普通窝、1 个学院窝、6 条母本配对记录。11 个居民的实例 ID 均能匹配同账号宠物库。
- `0x0152.field3`、`0x015C.field12` 提供当前/目标场景资源 ID；样本 30001 有上述居民，30002 带同一份家园布局但无室内居民，蛋神明确排除 30002；10003 样本没有 home_info。
- 游戏场景提供 `layEggCouples`，一个母本可有多个父本。距离算法只产生候选，不替代有效的游戏配对。

证据定位：解包产物 `home_scene.pyc` 的 `decode_home_scene` 原源码行 218–305；`web_runtime.pyc` 的 `CollectorService.home_info` 行 1506–1536；`webui/feature-pages.js` 的 `homePets`、`homePairingModel`、`homeMapMarkup`；`webui/home-breeding.js`。
本机详细证据在 `output/home-analysis-20261016/REPORT.md`、`sample-summary.json` 和反汇编文件中；这些是分析辅助，不是测试运行依赖。日志的 bytes 字段经过有损 JSON 转换，不能当作原始字节录制。

## 3. 状态、层次和契约

| 职责 | 唯一所有者与边界 |
| --- | --- |
| 原始包与字段树 | 现有 monitor/protocol 管线；不在抓包回调加入磁盘 IO |
| 字段含义、位置、候选与预测 | `domain/home.py`、`domain/home_breeding.py`；无网络、数据库、Vue 依赖 |
| 活动家园、会话、账号、快照版本 | `services/home_repository.py`；状态和数据同次加锁取齐 |
| 宠物个体与声音覆盖 | 现有宠物 repository/store 公共接口；不从 web 访问私有 `_store` |
| HTTP DTO | `web/payloads_catalog.py` 的家园边界；`/api/home` 继续复用现有鉴权和请求机制 |
| 页面筛选、视图、选中与显示排序 | Vue home page/composable；应用壳继续拥有账号代次、请求失效和唯一 WebSocket |

必须保持的 ID 关系：`instance_id → Pet.gid`；`base_conf_id → 物种目录`；`actor_id → 场景配对/离开`；`nest_guid → 家具/窝`。不得用 actor ID 低位查物种，也不得用背包成员推定入住。

`actor_id`、家具 GUID 等已确认 64 位标识在 JSON 前转十进制字符串；数值坐标、指标保持 number。发生契约变更时，同步 Python 载荷、TS 类型、运行时校验和相关消费者。

沿用 `uid/version/pending_deltas/complete/source`，A 中按最小范围完善 `source`：

| 条件 | source 与行为 |
| --- | --- |
| 当前展示账号没有可用家园快照 | `unknown`；空态 |
| 当前账号和活动会话的有效家园快照 | `observed`；显示采集观察结果 |
| 仍在目标家园，存在已确认相关但无法合并的数据 | `stale`；保留上次结果，提示待刷新 |
| 离开目标家园/当前会话失效后仍保留该账号上次结果 | `history`；显示上次观察，停止接受该场景的增量 |

`couples_stale` 独立表达配对是否待刷新；历史状态可同时保留配对待刷新的事实。`complete` 在没有完整性证据时继续为 null；不得因数量等于 11 就硬编码 complete=true。
不要额外建立另一套版本、账号状态或通用状态机框架。用户后续明确要求重启后读取家园信息，因此仅增加每账号最近一次快照的本地 SQLite 持久化，并在启动时按现有展示账号恢复为 `history`；云端查询、主动请求游戏、自动摆窝仍不纳入实现。

## 4. F04-U2-A：修正场景识别与快照归属（优先级 P0）

**目标**：只让自己有效家园的场景包更新家园快照；普通场景和排除场景不会抹掉居民。

主要文件：`spritelens/domain/home.py`、`spritelens/services/home_repository.py`、`spritelens/web/payloads_catalog.py`、`frontend/src/types/home.ts`、`frontend/src/pages/HomePage.vue`、`tests/test_home.py`。确有字段接入需要时再涉及现有会话通路；不另造监听器。

实施内容：

1. 删除/改正 `_entities_of` 所代表的错误布局路径，以及仅为该路径服务的假设、注释和测试。保留正确的 home_info/other_actors 解析；已知窝配置不要仅因删除错误路径而一并清理。
2. 从家园元数据保留 owner UID，按当前账号验证归属。缺 home_info、主人不符或响应失败时，不产生一份“空家园”覆盖好数据；自己的有效空家园仍应正常更新为空。
3. 按 `PacketEvent.session_id` 绑定活动场景，处理 `0x0152/0x015C` 的场景资源字段。已知 30002 必须排除，普通场景必须退出活动家园状态。样本仅确认了部分资源 ID，不在无证据时编造其它场景映射或全局白名单。
4. 切场景立即停止旧家园增量更新，保留同账号上次快照为 history；切账号按既有 AccountTracker 规则清旧账号内存。旧 session 不得继续写入新活动场景。
5. 账号身份尚未确认、会话归属不明时不推定为自己家园，不为等待身份建立新的缓存队列；收到后续有效身份/场景数据再建立活动状态。
6. 同步 source DTO 与 TS 校验。Vue 显示“已采集家园 / 上次家园观察 / 家园数据待刷新”等事实；不要将解析失败归因为必须依赖外部 API。

必要验收：

| 场景序列/输入 | 预期 |
| --- | --- |
| 本账号室内 home_info + 多居民/窝/配对 | 正确解析房间等级与全部已提供成员；actor 类型 10 不再成为房间等级 |
| 有效家园 → 10003 或缺 home_info 的场景 | 保留原家园，source=history |
| 有效家园 → 30002（仍带布局、无室内居民） | 保留原家园居民，不当作有效空室内快照 |
| 有效家园 → 他人家园 | 不写成自己的家园 |
| 当前账号有效空家园 | 允许清空居民，不能“始终保留非空旧值” |
| A 账号/旧 session → B 账号/新 session → 旧包晚到 | 不混账号、不恢复旧活动场景 |

复用 `tests.test_home` 和必要的 `tests.test_account_domain_contract`。将原先断言“等级 10、1 居民”的错误结构改成能复现真实字段语义的最小合成输入；保留有效 ID 精度、个体关联回归。本机样本 11/11/6 只作额外人工核对，不作为所有账号的数量规则。

## 5. F04-U2-B：正确合并目标家园增量（优先级 P1）

**目标**：相关变化及时合并，无关 NPC/动画不累计成“家园变化”，同一批有效更新不因无关项丢失。

主要文件：`domain/home.py` 的 `apply_home_delta`、`services/home_repository.py`、`tests/test_home.py`；必要的 source/pending 文案沿用 A 的契约。

实施内容：

1. 只在 A 建立的本账号活动家园会话中处理 `0x0413/0x0414`。其它场景消息不改家园数据、版本或 pending 计数。
2. 区分三类结果：已识别更新、可确认无关的项、相关但无法解析的项。当前 `None` 若无法表达，采用本域最小返回结构，不创建通用解析框架。
3. 每个 action/actor 独立合并；一个无关 actor 不得撤销同批有效居民/场景蛋变化。只对真正相关的未解析项累计 pending。
4. 已知居民可按 actor ID 接受稀疏更新；字段缺失保留原值，显式坐标 0 是有效更新，不能把所有 0 当作未提供。实例关联、窝引用清除等按字段存在性处理。
5. 保留 packed/unpacked 离开 ID、场景蛋增删和窝内居民引用一致性。居民成员或确认相关的变化后标记配对待刷新；无关 NPC 不应使配对失效。
6. 新有效全量快照清 pending 并替换配对；在新快照到来前保留旧记录的过期事实，候选继续明确标推导。

必要验收：同批“有效居民更新 + 无关 NPC”；无变化/重复消息；缺字段与显式原点坐标；离开居民/蛋；真正相关未知项；离开家园后的通用变化。合并进已有家园用例，不逐个私有 helper 写镜像测试。

## 6. F04-U2-C：补全资料与统一预测数据（优先级 P1）

**目标**：参考页展示所需的居民资料、母本蛋种和预测从本地来源一次组织正确，后端计算结果交给前端展示。

主要文件：`domain/home_breeding.py`、`web/payloads_catalog.py`、`web/server.py` 的家园参数接线、`frontend/src/types/home.ts`、`frontend/src/composables/useHome.ts`、`web/static/app.js` 的现有刷新桥。需要声音来源时仅扩展现有宠物服务公共读接口；复用 `domain/measurements.py`、现有奖牌规则、`egg_catalog`，不复制整个宠物载荷。

实施内容：

- 按同账号 instance ID 合并个体，base ID 联查物种；资料缺失允许显示已知居民，不把未知性别/声音补成猜测值。
- 补体型百分位、奖牌和母本蛋种/图片；仅提供本页需要的字段，避免对每个居民调用整套详情构建。
- 先核对现有声音契约和手动覆盖通路。家园使用统一有效声音来源；确认存在的手动 0 dB 必须保留，无值传 null。不得在 Vue 单独用真假值修补，或修改全项目 Pet.voice 的语义来迁就本页。
- 继续沿用已观察工具规则：普通窝双亲各 30% + 随机 40%，学院窝分支、多父本等权和声音均值向零取整。规则改动进入现有 `home_breeding.py`；若必须修改目前塞在 web 内的预测，局部移入该域模块，HTTP 层仅转换结果。
- 游戏有效配对优先；过期关系的范围候选单独标来源，不以距离重新覆盖场景配对。未知亲本保留未知比例；随机部分并非排除亲本性格。
- 每个父本及声音预测项保留 `father_actor_id`，前端按 ID 建 key。两个同名“鸭吉吉”仍是两个不同个体。
- 家园展示不仅依赖 home_version，还依赖同账号宠物资料/声音版本。复用应用壳现有宠物变化通知，使活跃家园页按需刷新；离页/切号/旧请求失效继续走现有通路，不新建 WS 或轮询。

必要验收：同账号个体命中/缺失/跨账号不命中；普通/学院窝、缺父本与多个同名父本；有效 0 dB 与缺值；手动声音变化后页面与预测更新；取消/切号后旧响应不覆盖。复用现有预测与账号用例，只给未覆盖的数据规则补回归；不要在 domain、payload、Vue 三层重复测同一公式。

## 7. F04-U2-D：居民预览与配对交互（优先级 P2）

**目标**：将目前概览页补成参考图中的“精灵预览 + 配对关系”工作页，沿用 SpriteLens 主题。

主要文件：`frontend/src/pages/HomePage.vue`、`pages/home.css`、`composables/useHome.ts`、`homeBridge.ts`、现有详情接线；可按真实职责拆家园卡片和配对展示组件，不重新搭整个应用壳。

实施内容：

1. 页面头部保留角色/采集信息，家园区域提供搜索、预览/位置切换和配对模式。刷新动作语义为读取本地采集结果，提示进入游戏家园才会得到新场景数据。
2. 居民卡显示形象、性别、名称、性格、蛋组、有效声音、身高/体重百分位、普通/学院窝标记。母本卡联动显示蛋种、性格分布和声音预测范围。
3. 右侧显示已确认配对，区分普通/学院配对及多父本；配对模式按关系连通组排列并着色。颜色和布局用于阅读，不改变游戏关系。
4. 搜索覆盖名称、物种、性格、蛋组。点居民卡复用现有宠物详情，用 instance_id 定位；缺个体资料时说明缺失，不打开其它同名宠物。
5. 长按拖动仅改变本地显示顺序。按账号使用项目现有偏好通路保存；若没有合适的持久化字段，先补一个有限字段，不读写旧 app.js 私有状态或引入通用布局系统。
6. 概率图使用现有图形能力或 CSS/SVG，不增加图表依赖。加载/错误/重试保留现有数据和主布局；未知、历史与待刷新有可读状态，移除无条件的“完整性未确认”固定占位。

验收：已有 11 居民场景展示完整，6 条母本配对及同名父本对应准确；筛选、详情、分组、排序、切号均保持身份；普通窗口和窄窗口无溢出，列表与右栏各自可读，重复刷新不跳布局。Vue 构建包含类型检查；交互做必要目视检查，不新增整套浏览器测试。
