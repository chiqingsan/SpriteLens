# 页面驻留内存分摊测量（PERF03，2026-10-26）

状态：PERF03 的分摊测量已完成，本轮不实施离页局部释放；真实桌面整机与长期运行仍按原口径待验收。
读者：维护者、后续实现模型与复核者。
用途：补齐 [内存与性能修复交接](MEMORY_PERFORMANCE_HANDOFF_2026-10-24.md) 中 PERF03「每页 heap/DOM/图片占用分摊证据」的缺口，记录口径、结果与后续候选。
维护边界：本文是带日期的测量证据；持续状态只维护在 [ROADMAP](../ROADMAP.md#perf-系列内存与性能优化2026-10-24)。本轮未修改业务代码。

## 1. 结论摘要

- **驻留有界，不是泄漏**：11 个页面各访问一次后进入平台；第 3–10 轮渲染进程私有内存合计 613–619 MiB，DOM 节点数恒定 8458，JS heap 15.6–17.6 MiB，没有逐轮增长。
- 从「只打开采集页」基线约 315 MiB 到「全部页面驻留」约 619 MiB，会话内增量约 **+304 MiB**。
- 单页隔离归因（每页单独进程，含共享启动成本，只能当上界与排序用）：planner +107、handbook +86、egg-dex +66、egg-box +49、breeder-library +38.5、home +38、collection-lines +34、colors +39.6、nearby +20、pets +20 MiB。各项相加约 +450 MiB，高于会话内 +304 MiB，说明每页数字重复计入了 Vue 运行时、首次加载等共享成本，不能逐页相加。
- 释放上限实验：去掉全部隐藏页 `img` 的 `src` 后 −127.27 MiB，再清空非活动页动态 DOM 后 −10.7 MiB；逐页顺序释放中图片共 −56.35 MiB，DOM 拆除在 GC 触发时一次性再 −107 MiB。可释放量约 **127–180 MiB**，但必须销毁页面（丢失筛选/滚动/草稿）且依赖 GC 时点，不能可靠逐页归因。
- 结论：现有桥只有 `pause()` 与 `unmount()`，没有「保留筛选、阅读位置、焦点、选中、草稿」的取消挂载—重挂载机制；直接离页卸载不满足 PERF03 验收，因此本轮只交付测量与决策，不实施释放。重页面局部释放作为后续候选另行单列范围。

## 2. 方法与口径

- **数据根隔离**：临时数据根只只读拷贝 `keys/`、`spritelens.sqlite(-shm/-wal)`、`pet-media-cache/`、`account-avatar-cache/`、`scene_checkpoints.json`、`config.json`；不写真实数据目录，不启停在线抓包，不提交录制/密钥。
- **装配**：`build_app_context(autostart=False)` → `LocalServer(ctx, port=0)` → pywebview 窗口 1440x810（`innerWidth x innerHeight` = 1426x773），WebView2 `Edg/155.0.0.0`，`devicePixelRatio=1.5`。
- **采样**：`performance.memory.usedJSHeapSize`、`document.querySelectorAll('*').length`、每个 `.page` 容器的节点数与图片数；渲染进程内存用 psapi `GetProcessMemoryInfo` 取私有工作集，并按 `Win32_Process.ParentProcessId` 枚举子进程求和。
- **切换后等待**：会话导航每页 0.35 s；隔离单页每次切换后等 1.5 s 再采样。
- 未使用 Computer Use；不使用失效缓存或伪造数据填充页面。

三类实验：A 会话内 10 轮固定导航（看是否平台化）；B 单页独立进程（尝试逐页归因）；C 满载后释放（测可释放上限）。

## 3. 实验 A：10 轮固定导航

访问顺序固定为 11 个页面（pets、handbook、egg-dex、egg-box、breeder-library、planner、collection-lines、home、nearby、colors、capture），重复 10 轮，每轮同一顺序。

| --- | --- | --- | --- |
| 1 | 575.40 | 8458 | 16.12 |
| 2 | 605.36 | 8458 | 17.60 |
| 3 | 618.99 | 8458 | 16.01 |
| 4 | 618.69 | 8458 | 15.62 |
| 5 | 618.43 | 8458 | 17.16 |
| 6 | 614.94 | 8458 | 16.55 |
| 7 | 615.10 | 8458 | 17.47 |
| 8 | 614.45 | 8458 | 16.28 |
| 9 | 613.35 | 8458 | 16.68 |
| 10 | 614.79 | 8458 | 16.12 |

第 2 轮后不再增长（±3 MiB 属采样噪声），DOM 节点数从第 1 轮结束起恒定 8458。每页容器节点数首次与末次相同，例如 handbook 1024、pets 1455（120 张图）、breeder-library 1234、egg-box 872、planner 832、colors 716、home 712、egg-dex 692、collection-lines 594、nearby 47、capture 123。也就是说离页后这些页面既没有卸载 Vue 实例，也没有释放 DOM。

`switchPage` 目前对除采集页以外的页面只 `pause()`，`page-cached` 只影响布局保留方式（`display:block; visibility:hidden` 与 `display:none`），两种情况内容都继续驻留。

## 4. 实验 B：单页隔离归因

每页单独启动一次进程与窗口：界面就绪并加载宠物列表后，先点采集页采样 `capture_baseline`，再点目标页等 1.5 s 采样 `on_<page>`，回到采集页等 1.5 s 采样 `after_leave_<page>`。

| planner | +107.2 | +112.3 | 11.31 | 832 | 50 |
| handbook | +85.6 | +86.4 | 8.15 | 1024 | 85 |

## 5. 实验 C：可释放上限

先导航全部页面到平台，再逐项释放：

| 步骤 | 私有合计 (MiB) | 相对平台 |
| --- | --- | --- |
| A 平台 | 599.11 / 622.17（两次运行） | — |
| B 去掉全部隐藏页 `img` 的 `src` | 471.84 | −127.27 |
| C 再清空非活动页动态 DOM | 461.11 | −10.70（相对 B） |

逐页顺序释放（第二次运行，平台 622.17 MiB）：去掉 pets/ handbook / egg-dex / egg-box / breeder-library 的图片 `src` 依次为 −8.87、−27.87、−9.01、−4.59、−6.01 MiB，其余页面为 0，合计 −56.35 MiB；随后清空 DOM 时多数步骤为 0，直到 collection-lines 一步一次性 −104.50 MiB，再逐步回落到 459 MiB。

结论：可释放量约 127–180 MiB，主要是图片解码与页面 DOM/V8 侧结构；但释放必须销毁页面内容，而且大量回收只在 GC 实际运行时出现，单步差值受 GC 时点影响（collection-lines 隔离测量仅 +27.6 MiB，却出现 −104.50，判定为 GC 噪声，不作为页面成本）。

## 6. 与 `page-cached` 的关系

被 `page-cached` 保留布局的三页（pets、egg-box、nearby）隔离增量分别为 +12.0、+48.7、+13.2 MiB，明显低于 planner/handbook/egg-dex。因此收缩缓存集不是主要收益来源，且会让列表重新挂载、回顶或闪动，与「后台更新不得造成 UI 闪动」的既有要求冲突，不建议用缓存集换内存。

## 7. 未覆盖与后续候选

未覆盖：

- 多窗口场景（主窗 + 雷达窗同时打开）、不同 DPI/缩放与最小窗口尺寸。
- 真实游戏流量下的驻留（本轮数据集为隔离回放后的本地库）。
- 长时间空闲后的 GC 稳态（本轮每次采样间隔较短）。
- 冻结 EXE 与真实桌面整机的绝对内存。

后续候选（需要单独列范围并批准）：对 planner、handbook、egg-dex 做「离页局部释放」，前置条件是每页提供轻量状态保存/恢复（筛选、滚动、焦点、选中、草稿）与重挂载不闪动验证，并复用相关 composable 回归；未满足前不实施，避免以状态丢失或闪动换内存。
