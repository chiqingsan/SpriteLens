## 重复资源

**96 组文件字节完全相同，313 份额外副本，原始去重上限 4.22 MiB。**
像素完全相同但编码不同的单帧图还有少量补充，合计上限约 4.23 MiB，不与前者相加。

主要重复在：

| 类别 | 重复组 | 额外副本 | 该类别内字节去重上限 |
|---|---:|---:|---:|
| pets 小图 | 52 | 212 | 1.60 MiB |
| fit 头像 | 16 | 34 | 1.36 MiB |
| 立绘 | 7 | 25 | 0.81 MiB |
| 派生用头像源版本 | 16 | 34 | 0.30 MiB |
| 旧奖牌图标 | 5 | 8 | 0.15 MiB |

例：`pets/3594.webp` 与包含 3623–3658、8013–8017 等 ID 的 81 个文件字节相同；
`5001-normal-portrait-fit.webp` 与 5047–5051 的 fit 文件也相同，立绘同样重复。
同一图片对应多个稳定业务 ID 不代表这些 ID 应合并，也不代表来源错误。

实际去重必须保留物种/形态/异色 ID，让资源 URL 映射引用一个规范文件；
旧 `/static/pets/{id}.webp` 是动态路径，需同步 URL 生成与全部消费者，不能只删除重复路径。
不按近似轮廓或感知哈希合并图片，防止误合并异色、形态或细节不同的资源。

## 压缩实验与画质边界

使用本项目 .venv 的 Pillow/libwebp 1.6.0，在忽略的 `.guishot/asset-audit/` 做副本实验。
正式图片、映射、来源报告与打包配置均未修改。

头像/立绘按文件大小分位选择各 10 张，兜底图/蛋图/旧奖牌各 6 张，
比较同尺寸 Q90/Q85/Q80、有透明通道保持的 WebP 与无损 method=6。
有损 alpha_quality=100；无损使用 lossless=True、exact=True，quality=80 在此表示编码努力，
不表示损失像素质量。仅采用比原文件更小的输出。

画质检查在原尺寸与 112px 显示尺寸下，把图分别叠在暖白与深色背景，
对内容边界计算 RGB PSNR；它是相对现有已编码图片的误差指标，不是相对官方原始素材。
PSNR 不能替代视觉判断。原尺寸重编码会引入损失，不声称 Q85 与原无损图逐像素相同。
全量 PNG 无损转码另核对 RGBA 逐像素一致，头像有损转码核对尺寸和 alpha 完全不变。

人工对比包含复杂色块/描边头像 5009、3111 的 256px 原尺寸：Q90/Q85 保留整体轮廓与色块，
Q80 更容易看到边缘软化或颜色变化。正常卡片/详情为 64–112 CSS px，256px 仍为高 DPI 保留。
初次实施倾向 Q90 起步，评估 Q85；不同时缩分辨率，不压缩业务色表或用有损方式处理色卡/矢量图标。
立绘已是有损编码，第一轮优先保留 512px；后续需要压缩时从可追溯源重建，避免反复有损重压。

批量实测（全部在隔离副本中，正式资源未替换）：

| 转换 | 数量 | 原体积 → 输出体积 | 节省 | 校验 |
|---|---:|---:|---:|---|
| fit 头像，同尺寸 Q85 WebP / method=6 | 817 | 31.52 → 9.12 MiB | **22.40 MiB / 71.06%** | 尺寸与 alpha 逐像素不变；RGB 为有损 |
| 蛋图标，PNG → 无损 WebP / method=6 | 223 | 2.94 → 2.01 MiB | **0.93 MiB / 31.68%** | RGBA 逐像素一致 |
| 旧奖牌图标，PNG → 无损 WebP / method=6 | 52 | 0.97 → 0.67 MiB | 0.30 MiB / 30.90% | RGBA 逐像素一致；若整组从发行包排除，不再累加此收益 |

817 个头像、223 个蛋图与52个旧奖牌候选都比原文件小。PNG 当前没有 ICC 配置，少量 sRGB/dpi 标记
不改变本次像素一致性验证；实际网页颜色/透明边缘仍应在最终发布验收中核对。

头像采样（按体积分位各 10 张，所有有损样本 alpha 均完全不变）：

| 参数 | 样本累计节省 | 112px PSNR 最低 / 平均 | 判断 |
|---|---:|---:|---|
| 更高努力无损 method=6 | 1.26% | 像素完全一致 | 效果小；不作为主要瘦身手段 |
| Q90 / method=6 | 66.60% | 39.73 / 43.98 dB | 首次实施倾向的质量档位；全量体积尚未实测 |
| Q85 / method=6 | 71.17% | 38.49 / 42.31 dB | 已有全量体积实测；适合在视觉验收后采用 |
| Q80 / method=6 | 74.03% | 37.60 / 41.10 dB | 比 Q85 的进一步收益有限，边缘更容易变化 |

立绘 Q85 同尺寸采样节省约 17.94%，112px PSNR 最低 45.65 dB；兜底小图 Q85 仅约 10.23%。
它们已经有损，优先级低于 fit 头像。蛋图若改用 Q85 虽更小，但采样原尺寸 PSNR 最低仅约 29.59 dB；
本次建议采用无损格式转换，保留细节。以上数值是相对当前编码图片的抽样指标，不是画质保证。

对当前文件集合模拟组合策略，按原始 SHA 组去重，用实际转码文件大小替换对应资源大小：

| 方案 | 资源体积 | 相比 70.96 MiB 的节省 |
|---|---:|---:|
| 仅发行清单排除候选 | 62.38 MiB | 8.57 MiB |
| 排除候选 + 精确去重 + 蛋图无损 WebP | **57.69 MiB** | **13.27 MiB / 18.70%** |
| 上述方案 + 全部 fit 头像 Q85 | **36.27 MiB** | **34.69 MiB / 48.88%** |

组合已扣除排除项与重复图的重叠，不把 22.40、4.22、8.57 MiB 直接相加。
这是根据当前文件大小计算的候选发行资源集合，并非已完成发布：URL 映射改写会轻微改变 JSON/代码体积，
尚未实际生成新发行包或实测 exe 大小，亦未对有损版本做全页 WebView2 验收。
候选参数与采样指标只代表本次输入，不直接写入生产默认配置。

## 推荐实施与验收

1. 先建发行资源白名单，保留生成源与报告在开发侧；做缺图/未知数据回退、图标、主题和打包验收。
2. 精确内容去重，同步稳定 ID→资源 URL 映射和动态 fallback 路径；来源关系继续保留。
3. 蛋图标优先无损 WebP，同步 `.png`→`.webp` 的全部引用、来源输出清单与测试。
4. fit 头像在导入工具中一次生成 Q90/Q85 派生图，记录转换参数/输出 SHA；不要只临时压一遍，
   否则下次 sync_portraits 会重新生成无损大文件。
5. 校验覆盖率/尺寸/透明通道/引用与组合收益，浏览器三主题、WebView2/实际 exe 验收后才发布。

本轮仅审计，正式资产 SHA256 与审计输入逐项一致；不需要为报告重跑与素材无关的业务测试。
本机详细清单、逐图候选和对比图在 `.guishot/asset-audit/`，不提交本机临时样本或图片副本。
