# 解码分配复测与消费者审计（PERF06，2026-10-26）

状态：PERF06 的复测与结论已完成，本轮不修改协议解码表示；真实桌面与长期运行仍按原口径待验收。
读者：维护者、后续实现模型与复核者。
用途：按 [内存与性能修复交接](MEMORY_PERFORMANCE_HANDOFF_2026-10-24.md) 的进入条件，在 PERF01 之后复测剩余解码分配，并审计字段消费者，决定是否值得减少展示字段与中间树。
维护边界：本文是带日期的测量证据；持续状态只维护在 [ROADMAP](../ROADMAP.md#perf-系列内存与性能优化2026-10-24)。本轮未改业务代码。

## 1. 结论

- PERF01 关闭事件历史后，桌面管线结束时解码相关存活分配约 **1.5 MiB**，整段采样峰值约 **22.7 MiB**。
- 峰值基本等于「单个最大登录包的解码树」：160,856 字节的 `ZoneLoginRsp` 一次生成 53,246 个字段节点，schema 字典树驻留 15.2 MiB、构建峰值 21.8 MiB，wire 树另占 7.8 MiB；两棵在事件消费完后全部释放（残留 0.4 KiB）。
- 也就是说，剩余解码分配是**有界的瞬时峰值**，不是随运行时间增长的驻留；PERF01 之后没有再次出现与事件保留相关的解码驻留。
- 消费者审计显示字段树同时被业务提取（`raw`/`children`）、事件日志（整棵 `decoded` 序列化）与诊断展示使用；删除或改写展示字段会改变事件日志与诊断契约，收益（约 1.8 MB 展示字符串）与峰值相比很小。
- 因此本轮决定**不实施**协议表示改造，保持现有 `wire` → `schema` 树契约；后续若出现「大包高频出现」导致解码峰值持续占用，再按本文件口径复测后单列范围。

## 2. 方法与口径

- 输入：本地录制 `capture_20261025_154244.jsonl`（24,953,029 字节）前 3,000 段；只读，KeyStore 保存方法为内存替身，不写真实密钥、数据根与事件日志。
- 管线：`MonitorService(keep_event_history=False)`，真实 `OpcodeCatalog` 与 schema 库，另用包装库统计每次解码的节点数与文本/原值数量，并记录采样内最大 `payload`。
- 分配观测：`tracemalloc`（25 帧）在喂入前启动，记录当前/峰值；结束时按文件统计存活分配。
- 单包测量：对采样内最大 payload 分别调用 `wire.decode_wire` 与 `schema.decode`，用 `tracemalloc.get_traced_memory()` 在持有引用的前后差取驻留字节，删除后 `gc.collect()` 再确认释放。
- 未使用 Computer Use；不启停真实采集。

### 3.3 与 PERF01 的关系

PERF01 之前，隔离回放同输入的结束态 tracemalloc 为 +22.25 MiB（保留 2,000 条事件），关闭历史后为 +1.06 MiB；本次在同一录制前 3,000 段上复测到 +1.52 MiB 结束态、+22.7 MiB 峰值，与「峰值 ≈ 单个大包解码树、结束态只剩管线自身」的解释一致。

## 4. 消费者审计

- 业务提取：`spritelens/domain/pets.py`、`identity.py`、`egg_box.py`、`home.py`、`pet_locations.py`、`scene.py` 等读取 `raw`（20 处）与 `children`（31 处），依赖强类型原值与嵌套结构；`value` 在 Python 侧没有直接消费者。
- 诊断序列化：`spritelens/services/event_logger.py:356` 把整棵 `event.decoded` 写入事件日志 JSONL，`tools/analyze_recording.py` 与回放 CLI 复用同一结构；`name`/`value`/`text` 决定日志可读性。
- 事件对象契约：`spritelens/events.py` 的 `PacketEvent.decoded: list[dict]` 是监听器公开结构，UI 诊断与后续日志都按此消费。
- 结论：删字段或改成惰性映射会同时改变业务补全、日志格式与诊断行为，属于交接中标注的高风险协议契约变更；在本轮数据里它只能影响一个瞬时峰值，收益不足以抵消风险。

## 5. 未覆盖与复测条件

未覆盖：高频大包场景（例如连续登录/背包刷新）、真实游戏流量下的事件速率、冻结 EXE 与整机峰值；本轮采样只覆盖单个录制前段。

复测条件：若后续在线观测到解码峰值不再是单包上限（例如峰值随事件速率线性上升），或事件日志写入成为节拍瓶颈，再按本文口径复测并单列协议表示改造范围。
