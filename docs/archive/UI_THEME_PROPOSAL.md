# 竞品启发与 SpriteLens 主题系统建议

日期：2026-10-12。状态：设计建议，尚未实施主题系统。

## 1. 检查范围与结论

检查了蛋神助手 v1.1.6 解包目录的 `webui/` HTML、CSS、JS，以及
`D:/code/meow toolkit` 的主题模型、主题页、运行时、持久化和相关测试。
本次为静态源码分析，没有运行竞品可执行文件；文件存在或代码声明不等于真实运行验收。

建议保留 SpriteLens 当前的「分组导航 + 紧凑状态栏 + 网格 + 右侧筛选/详情」布局，
下一步完善数据解释、界面偏好与主题基础，再扩展繁育和收集任务。
蛋神适合参考业务交互，meow toolkit 更适合参考主题管理分层。

## 2. 蛋神做得好的地方

| 观察到的实现 | 对 SpriteLens 的启发 | 建议顺序 |
| --- | --- | --- |
| 蛋组筛选支持任一匹配和同时匹配；性别、性格、奖牌、获取方式可组合 | 优先补蛋组筛选；其他条件先确认数据字段可靠 | 高 |
| 详细条件可固定为快捷筛选，快捷项和详细条件共用状态 | 用户能把「雄性 + 某蛋组 + 某性格」等常用条件保存下来 | 中 |
| `display` 独立控制身高、体重、声音、蛋组、性别符号等显示字段 | 展示偏好独立于筛选；隐藏声音列不应改变查询结果 | 高 |
| DesktopStorage 同时使用本地缓存和 `/api/ui/preferences` 持久化 | 重启保留视图、显示字段、折叠状态；使用应用配置作为持久化来源 | 高 |
| 详情有个体/精灵蛋参考切换；色卡支持选择精灵预览 | 详情应提供可解释的比较依据，色卡从统计表发展为预览工具 | 中 |
| 配窝、产线、目标捕捉围绕用户任务组织；算法模型与页面拆开 | 后续功能按「找精灵 → 判断能否配对 → 看缺口」串起来，复用 domain 规则 | 后续 |
| 动效可关闭，并响应 `prefers-reduced-motion` | 外观设置可以单独提供动效偏好；保留系统减少动效优先级 | 中 |

证据定位（相对于竞品解包目录 `webui/`）：

- `app.js:5`：页面、筛选、显示字段与详情模式状态。
- `app.js:526`：组合条件；`:545` 蛋组任一/同时匹配。
- `app.js:734`：快捷条件固定与详细状态同步。
- `desktop-storage.js:6`：偏好保存接口；`:19` 明确的可记忆字段列表。
- `app.js:845`：个体与精灵蛋参考切换；`atlas-preview.js:91`：精灵/色卡预览结构。
- `motion.js:8`：系统减少动效；`planner-core.js:1`、`collection-model.js:1`：模型与页面拆分。

### 不宜直接照搬的实现

1. **悬停放大**：`app.js:1041` 把卡片复制放大到 2.08 倍。密集网格中会遮挡相邻项，
   SpriteLens 保留点击/Enter 打开详情；未来如需预览，单独展示简短提示即可。
2. **CSS 补丁累积**：竞品 `app.css` 共 1112 行，包含 855 次 `!important`，
   还有 `readability.css`、`responsive.css` 多层覆盖。参考最终体验，主题实现应收敛变量，
   避免每个主题追加一套组件选择器。
3. **游戏箱位**：竞品背包使用 `box`、`slot`，并标出有筛选命中的箱子（`app.js:1094`）。
   SpriteLens 尚无可靠箱位，继续称「浏览页」；有协议证据后再实现真实箱位视图。
4. **业务百分比**：竞品提供身高/体重百分比筛选，但当前 SpriteLens 的
   `height_pct`、`weight_pct` 是相对于本次筛选结果最大值的比例（`web/payloads.py:127`），
   并非物种真实范围或统计百分位。筛选变化会改变比例，不能据此判定「最大体型」。
   先确认物种/蛋基础上下限与公式，再提供这一筛选；暂时用 m、kg 等绝对值。

本次没有发现独立的全局主题选择/导入导出实现；源码中的部分 `theme` 字段
是声音、身高、体重控件的样式分类，不能据此认定已有主题系统。

## 3. meow toolkit 可以借鉴什么

- `ui/themes.py`：主题数据、颜色 token 描述、默认补全、另存、导入导出、内置主题保护。
- `ui/view_models/theme.py`：当前主题与用户主题管理，不依赖 Qt 控件。
- `repositories/theme.py`：持久化窄接口。
- `ui/theme_runtime.py`：独立弹窗解析当前主题，读取失败回落默认。
- `ui/styles.py`：组件样式集中消费语义颜色，部分交互色由基础色推导。
- `tests/test_theme_view_model.py`、`test_theme_repository.py`、`test_theme_runtime.py`：
  保存、恢复、删除当前主题回落、独立窗口接入等行为已有测试。

### 迁移时需要调整

- meow 使用 Qt/QSS，SpriteLens 使用 Web/CSS：迁移数据结构与职责分层，重新实现渲染适配。
- meow 的八位 hex 是 `#AARRGGBB`，CSS 是 `#RRGGBBAA`。
  例如 meow 的 `#b2142b21` 应转成 CSS `#142b21b2`，不能直接复制。
- meow 导出包含 `schema`、`version`，但目前 `import_data` 没有严格校验这两项，
  颜色归一化对无法识别的文本也会原样返回。新主题格式应验证版本、字段及颜色。
- meow 改色后直接持久化；SpriteLens 编辑器建议使用「草稿预览 → 应用保存 / 取消恢复」，
  避免尝试配色就覆盖已保存主题。
- meow 的 `accent` 是主强调色，SpriteLens 当前 `--accent` 是浅黄绿导航选中底。
  应按语义映射，不能按变量同名直接映射。

## 4. 主题系统设计

### 4.1 用户入口

系统导航新增「外观」。第一版包含：

1. 内置主题卡：自然绿浅色（当前风格）、中性浅色、森林深色。
2. 「跟随系统」：明确使用默认浅色/深色主题配对，监听系统模式变化。
3. 即时预览；应用、取消、恢复默认。
4. 独立的舒适/紧凑密度偏好与动效偏好。

第二版再增加基础改色、另存主题与 JSON 导入导出。高级 token 编辑折叠，
普通用户只需要调整主色、背景、侧栏与文字。

### 4.2 明确三类数据

| 类型 | 内容 | 切换主题的影响 |
| --- | --- | --- |
| 外观颜色 | 背景、面板、文字、边框、主按钮、选中、状态提示、焦点环 | 更换颜色组合 |
| 界面偏好 | 网格/表格视图、密度、显示字段、折叠状态、动效 | 各自保存，不随配色被覆盖 |
| 游戏展示数据 | 系别色、真实色卡、精灵图片、天赋阶等 | 保留业务含义；调整周边底色或标签文字以保证可读 |

主题不包含业务筛选和布局代码。保存的筛选方案单独管理，避免重启隐藏条件导致误以为数据丢失。

### 4.3 token 结构

保持现有组件选择器，建立明确的主题契约，推荐字段：

| 组 | 字段示例 |
| --- | --- |
| 表面 | `background`、`surface`、`surfaceRaised`、`surfaceHover` |
| 文字与边框 | `text`、`textMuted`、`border`、`borderMuted` |
| 主操作 | `primary`、`primaryHover`、`onPrimary` |
| 选中与焦点 | `selectionBg`、`selectionText`、`selectionBorder`、`focusRing` |
| 导航 | `sidebarBg`、`sidebarText`、`sidebarMuted`、`sidebarHover` |
| 状态 | `success`、`successBg`、`warning`、`warningBg`、`danger`、`dangerBg` 及对应文字 |
| 其他 | 遮罩、浮层阴影、协议解码高亮与图表颜色 |

用显式适配表映射现有变量，例如 `primary → --teal`、`onPrimary → --white`
需先分离主按钮文字与其他白字用途；`selectionBg` 根据组件对应 `--teal-soft` 或
`--accent`，不能把所有旧变量统一换成同一个值。先完成角色梳理，再建立映射。
深色主题提供完整语义颜色，用户主题缺失字段按所选深/浅基底补全。

`app.css` 保留结构、尺寸与组件规则，主题预设放独立 `themes.css`；
`theme.js` 负责模式选择、token 应用、预览和恢复。使用根节点属性/变量切换，
无需重建宠物 DOM；切换时保留选择、滚动与筛选。

### 4.4 文件格式

下面是用户主题的部分覆盖示例；其余字段由 `forest-dark` 基底补全，
内置主题本身提供完整颜色契约：

```json
{
  "schema": "spritelens-theme",
  "version": 1,
  "id": "my-forest",
  "name": "我的森林",
  "mode": "dark",
  "base": "forest-dark",
  "colors": {
    "background": "#172019",
    "surface": "#202b22",
    "text": "#edf3e7",
    "primary": "#a6c887",
    "onPrimary": "#192413"
  }
}
```

- 接收明确颜色类型，统一存为 CSS 格式；禁止任意 CSS、脚本和远程资源字段。
- 校验 schema、版本、模式、允许的基底及 token；未知字段报清楚的错误。
- 主色改动时联动预览 hover、柔和底、焦点环及按钮文字；仍需检查每个前景/背景组合。
- 内置主题不可覆盖；导入同名 ID 时创建新用户 ID，主题名称可编辑。
- 需要复用 meow 主题时提供显式转换器：转换 alpha 顺序，并输出字段映射/缺失提示。

### 4.5 持久化与启动

使用 SpriteLens 已有 JSON SettingsRepository，无需引入 SQLite 主题库：

- `appearance.theme`：主题选择与跟随系统模式。
- `appearance.user_themes`：经过校验的用户主题。
- `ui.density`、`ui.motion`、`ui.pet_view`、`ui.pet_fields`：独立偏好。

SpriteLens 每次启动使用随机端口，浏览器 origin 会变化，localStorage 不能作为唯一持久化来源。
应用配置为准；前端缓存最多作启动加速。必要时增加鉴权的 appearance GET/POST 接口，
bootstrap 同步载入外观状态，保存成功后再显示「已保存」。现有配置仓库会记录写入错误，
新保存路径应把失败返回给界面，避免假成功。

首次内容展示前解析已保存主题，超时/损坏回落当前自然绿；不要出现深色选择每次启动先闪白，
也不能为了等外观请求无限隐藏主界面。预览仅改内存，保存使用现有临时文件原子替换机制。

### 4.6 可读性与验证

- 正常正文目标对比度 ≥4.5:1；焦点/重要控件边界目标 ≥3:1。
- 半透明颜色按最终叠加背景检查；不要直接拿带 alpha 的原色计算。
- 第一版优先不透明面板，保证网格、矩阵、协议流的可读性。
- 标签文字独立选色，色卡真实色值和精灵图片保持原样。
- 测试：非法主题回落、保存重启、导入冲突、取消恢复、系统模式变化、meow alpha 转换。
- 界面验收：三主题 × 网格/表格/图鉴/矩阵/色卡/协议流/弹窗，含选中、禁用、错误与加载态；
  检查 1440/1280/960/640px，主题切换不丢选择与滚动。

## 5. 后续实施顺序

1. **梳理数据含义**：体型比例注明比较基准；补齐可用蛋组筛选，不把当前结果最大值当成物种上限。
2. **主题基础**：清点语义变量，隔离预设，完成三套内置主题及应用配置持久化。
   新功能进入独立主题模块，避免继续扩张 `app.js`。
3. **外观与偏好页面**：预览/应用/取消/恢复，记忆视图和显示字段；密度不靠全局缩放文字实现。
4. **自定义主题**：基础改色、另存、JSON 导入导出与对比度提示。
5. **业务体验**：保存筛选方案、跨页比较、色卡精灵预览；再推进智能配窝、产线缺口和收集进度。

本轮建议的首个可交付范围：自然绿浅色 + 中性浅色 + 森林深色、跟随系统、
独立外观模块、持久化、预览与取消、全页状态验收。主题编辑器放在这一版稳定以后。
