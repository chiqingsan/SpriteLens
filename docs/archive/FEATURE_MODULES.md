# SpriteLens 功能模块规划（面向 UI/UX 设计）

> 历史文档：本报告写于项目仍名为 RocoPeek 时期，文中的「本项目/我们」
> 即现在的 SpriteLens；结论与实测数据保留原样，仅项目名已随迁移更新。

> 依据：本地协议盘点（`data/schemas/opcodes.json` 1627 条 opcode、`messages/all.json` 3458 条消息定义）
> + 实测里程碑（宠物仓库 160 只端到端验证通过）
> + 市面同类工具调研（2026-10-09）。
>
> 本文只解决一件事：**把"抓包能拿到的数据"翻译成"可扩展的功能模块"**，供 UI/UX 设计阶段划分页面与信息架构。

---

## 0. 结论速览

1. 我们的数据面是**全业务级**的：1627 条 opcode 覆盖宠物、背包、对战、任务、社交、邮件、商店、图鉴、地图、活动共 15 个业务域。
2. 市面同类工具（rocom-helper 99★ 等）**只做了宠物筛选 / PVE 摘要 / 地图**，全业务一站式消费端是空白。
3. **对战解包（PVE + PVP）是最大差异化机会**：协议里已有完整回合计/伤害/能量/buff/捕捉概率字段，但市面只有零散的摘要工具。
4. 三种数据形态决定三类 UI 交互：**快照类**（列表/详情页）、**事件流类**（实时滚动/告警）、**统计类**（图表/复盘）。

### 1.3 对战解包深度分析（你问的 PVE/PVP 能不能做）

**能，而且数据链条完整程度超预期**。以下是 schema 里已存在的关键结构：

| 能力 | 依据 schema | UI 表达 |
|---|---|---|
| 回合动作流 | `BattleRoundFlowReq`（cast_skill / change_pet / use_item / catch_pet / idle / skill_state / magic_op） | 战斗时间线：每回合双方做了什么 |
| 伤害明细 | `DamageRecord`（caster/target/damage/round/**is_critical**/**is_shield**/dam_type） | 伤害数字与暴击标记 |
| 伤害归因 | `BattleDamageInfo`（**restraint_type** 克制关系 / execution） | "为什么打这么多"：克制/暴击/护盾拆解 |
| 能量系统 | `BattleEnergyInfo`、`PetSkillRoundData`（cost_energy / hp_per_energy / cast_cnt） | 能量条与技能消耗面板 |
| Buff/Debuff | 71 个 `BuffData_*` schema（含 `_Skill`/`_PetBuff` 变体） | 状态图标与持续回合 |
| 回合结算 | `BattleRoundSettleInfo`（result / caster_pet_info / target_pet_info / last_damage_info） | 回合卡片 |
| **PVP 伤害统计** | `PvpPetDamageInfo`（idx + **damage_out**，即"每只宠打出的总伤害"） | **PVP 战报核心：伤害占比/贡献榜** |
| 捕捉概率 | `BattleCatchProbInfo`（ball_id + **catch_prob**） | **丢球时实时显示捕获概率**（市面无此功能） |
| 战斗收尾 | `BattleFinishPetInfo`（remain_hp / remain_energy / battle_max_hp） | 战报总结页 |

**结论**：可以做出 FFLogs 之于 MMO 的效果 —— 「**RocoLogs：洛克战报**」。
这是市面 62★ 的 `Roco-Kingdom-Protocol-Parser`（只输出文本摘要）完全没做深的方向。

## 2. 竞品格局与空白

| 竞品 | 形态 | 功能 | 数据来源 | 我们的差距/优势 |
|---|---|---|---|---|
| rocom-helper（99★） | 桌面+Web | 宠物筛选/繁育图谱/宠物雷达/捕捉日志/异色提示 | 抓包 8195（同我们） | 它只有宠物+PVE；我们业务域宽 10 倍 |
| rocom-capture（46★） | Go+Web | 宠物列表/捕获事件/实时地图/精灵蛋 | 抓包 8195 | 它有地图，我们可对标 |
| Protocol-Parser（62★） | 脚本 | 战斗回合/技能/伤害文本摘要 | 抓包 8195 | 我们要做**可视化成体系**的版本 |
| 洛克星盘/ROCO攻略/洛克多多 | 小程序 | 图鉴/孵蛋/配种/商人查询 | **手工录入** | 静态数据，无实时性 |
| BWIKI / 灰机 | Wiki | 图鉴/计算器 | 社区手工 | 静态数据源，可合作引用 |
| astrbot_plugin_rocom（149★） | QQ机器人 | 查档/家园/战绩/背包/商人 | **第三方 API（scam 第三方凭证代理是个灰色服务）** | 我们无需任何第三方账号 |
| RocoPilot（254★） | YOLO视觉 | 自动抓宠 | 屏幕识别 | 图像识别路线，与我们互补 |

**空白结论**：
- ❌ 没有"全业务一站式消费端"（背包/任务/邮件/商店/社交 全无人做）；
- ❌ 没有**对战复盘/战报分析**（PVE 与 PVP 都是空白）；
- ❌ 没有**掉落/收益统计**（把它做成"本场收益"面板）；
- ❌ 没有**捕获概率实时可视化**；
- ❌ 没有"数据导出/分享"（UIGF 之于原神，洛克没有对应标准）。

## 3. 功能模块规划（核心）

按 UI/UX 可直接映射的粒度，给出 **16 个模块**。每个模块标注：
- **数据依据**（opcode/schema）
- **成熟度**：🟢 已实测可用 / 🟡 协议就绪待实测 / 🔵 需额外（静态数据或社区）
- **UI 形态建议**
- **优先级**：P0 立即可做 / P1 验证后做 / P2 长期

---

### M1. 概览仪表盘 Dashboard ⭐首页
- **定位**：一屏看清"今天账号处于什么状态"
- **内容**：当前角色（头像/等级/区服）、宠物总数与近 7 天新增、今日对战场次与胜率、背包关键道具（球/药剂）、体力/能量、最近捕获、任务进度环
- **数据依据**：`ZoneRoleAttrRsp` / `ZonePlayerSyncNotify` / 各域快照聚合
- **UI 建议**：卡片网格（Dashboard），每卡片可点击下钻到对应模块
- **优先级**：P0（聚合已有数据，零新解析工作量）

### M2. 宠物仓库 Pet Box ⭐已实现，需扩展
- **定位**：全量宠物管理，替代游戏内的盒子
- **已做**：列表 + 搜索（名字/等级/血脉/天赋阶）
- **扩展点**：
  - 多维筛选（性格/性别/系别/稀有度/技能/来源）
  - 排序与分组（按战力/等级/捕捉时间/血脉）
  - **宠物详情页**（技能组/个体值/成长曲线/血脉树）
  - 「对比模式」：两只宠物属性并排
- **数据依据**：`ZoneGetPetInfoByPageRsp` → `PetDataInfoList.pet_data`（gid/conf_id/name/nature/gender/exp/level/blood_id/talent_rank/is_first_catch）
- **UI 建议**：左列表右详情（Master-Detail）；或卡片网格 + 详情抽屉
- **优先级**：P0（详情页）/ P1（对比/筛选器增强）

### M3. 个体评估 Pet Insight
- **定位**：把游戏内不显示的"个体值/天赋"翻译成人话
- **内容**：天赋阶可视化（S/A/B/C 或数值）、同种宠百分位、培养建议（喂什么/进化路线）
- **数据依据**：`talent_rank` / `blood_id` / `PetReport`（0x253 报告页）；建议值需静态规则表
- **UI 建议**：雷达图/评级徽章 + "该练/可放"标签
- **优先级**：P1（需要静态数据配合）

### M4. 对战观测 Battle Watch ⭐差异化核心
- **定位**：实时看懂每一回合（PVE 为主）
- **内容**：
  - 回合时间线（双方动作：放技能/换宠/用道具）
  - 伤害数字流（暴击/克制/护盾标记）
  - 双方血量/能量条
  - Buff/Debuff 状态面板
  - 技能效果提示
- **数据依据**：`BattleRoundFlowReq/Rsp`、`BattleRoundSettleInfo`、`DamageRecord`、`BattleDamageInfo`、`BattleEnergyInfo`、`BuffData_*`
- **UI 建议**：三栏战斗 HUD（敌/我方状态 + 中央回合流）；或 Overlay 悬浮窗（参考 ACT/WeakAuras）
- **优先级**：P1（待实测验证帧格式后开工，**最高价值**）

### M5. 战报复盘 Battle Review ⭐PVP 差异化
- **定位**：打完之后的"FFLogs 式报告"
- **内容**：
  - 伤害统计：每只宠伤害输出/占比/承伤（`PvpPetDamageInfo`）
  - 回合回放（时间轴拖动，按 `round` 字段重放）
  - 关键节点标注（暴击/克制/致命一击）
  - 胜率趋势（多场汇总）
- **数据依据**：`PvpPetDamageInfo` / `DamageRecord.round` / `BattleFinishPetInfo` / `ZoneSceneTeamBattlePetQueryRsp`
- **UI 建议**：独立"战报"页签；列表页（历史场次）+ 详情页（图表 + 时间轴）
- **优先级**：P2（最重、最亮；先在 M4 验证）

### M6. 捕获中心 Catch Center
- **定位**：把"丢球"变成有数据的过程
- **内容**：
  - 实时捕获概率（`catch_prob`，丢球时看到"这只 63%"）
  - 捕获成功/失败日志，连败计数
  - 异色/稀有提醒（`Beast` 系列 + 静态异色表）
  - 捕获位置回放（与 M12 联动）
- **数据依据**：`BattleCatchProbInfo` / `BattleCatchPetInfo` / `ZoneSceneReentrantBeastCatchRsp`
- **UI 建议**：实时浮层 + 日志流页签
- **优先级**：P1（实时概率是杀手级小功能）

### M7. 背包资产 Inventory
- **定位**：道具/资源总览，不打开游戏也能查
- **内容**：分类列表（球/药剂/材料/礼物）、数量、使用入口分析、与商店联动比价
- **数据依据**：`ZoneGetBagRsp` → 背包物品列表；`ZoneBagItemLimitNotify` 上限提醒
- **UI 建议**：分类标签页 + 表格；与 M13 商店模块交叉链接
- **优先级**：P1

### M8. 图鉴进度 Handbook Progress
- **定位**：收集度可视化与缺口提醒
- **内容**：已完成/未捕获清单、组别进度环、奖励领取提醒（`ZoneGetHandbookAward`）、主题图鉴进度
- **数据依据**：`ZoneHandbookChangeNotify` / `ZoneGetHandbookAwardRsp` + 静态图鉴表
- **UI 建议**：网格图鉴（已/未灰显）+ 进度条
- **优先级**：P1

### M9. 任务面板 Task Tracker
- **定位**：任务与章节进度追踪
- **内容**：主线/支线/世界等级任务列表、追踪状态、章节宝箱、活跃任务一键提示
- **数据依据**：`ZoneTaskInfoNotify` / `ZoneTaskQueryRsp` / `ZoneClimbChapterNotify` / `ZoneTaskTrackReq`
- **UI 建议**：列表 + 进度条；侧栏"当前追踪"
- **优先级**：P1

### M10. 掉落与收益 Loot Ledger
- **定位**：本场/本日获得了什么（参考 RuneLite Loot Tracker）
- **内容**：掉落事件流、按稀有度着色、单场收益汇总、历史累计
- **数据依据**：`ZoneGoodsRewardNotify` / `ZoneTaskRewardRsp` / `ZoneSceneRewardMinigameRsp` 等 `*Reward*` 族（172 条覆盖）
- **UI 建议**：实时滚动 + 收益汇总卡片
- **优先级**：P2（事件域待实测确认）

### M11. 社交 • 好友与串门 Friend & Visit
- **定位**：好友动态与串门管理（含拜访/访客记录）
- **内容**：好友列表、最近互动、串门邀请、历史访客
- **数据依据**：`ZoneFriendGetFriendListRsp` / `ZoneSceneApplyVisit*` / `ZoneFriendDataChangedNotify`
- **UI 建议**：列表 + 时间线
- **优先级**：P2（隐私敏感，需考虑模糊化）

### M12. 地图雷达 Map Radar
- **定位**：当前位置与资源点可视化（对标 rocom-capture 的实时地图）
- **内容**：当前场景/坐标、传送记录、资源点/稀有怪标注（静态图层叠加）
- **数据依据**：`ZoneSceneMoveReq` / `ZoneSceneTeleportNotify` / `ZoneWorldMap*` + 静态地图瓦片
- **UI 建议**：地图画布 + 图层开关
- **优先级**：P2（静态地图素材是重投入）

### M13. 商店与活动 Shop & Events
- **定位**：买什么划算 / 活动还剩几天
- **内容**：商店清单与刷新、兑换配方、活动阶段奖励倒计时、通行证进度
- **数据依据**：`ZoneShopGetInfoRsp` / `ZoneGetExchangeInfoRsp` / `ZoneGetPlayerActivityInfoRsp` / `ZoneGetBattlePassInfoRsp`
- **UI 建议**：日历 + 卡片清单
- **优先级**：P2

### M14. 邮件打理 Mail
- **定位**：一键看未领取附件
- **内容**：邮件列表、附件提醒、"有奖励未领"红点
- **数据依据**：`ZoneMailGetListRsp` / `ZoneMailGetAttachmentRsp`
- **UI 建议**：简单列表 + 红点角标
- **优先级**：P2

### M15. 时间线与统计 Timeline & Insights
- **定位**：把事件流变成"人生轨迹"
- **内容**：跨模块统一时间线（捕获/升级/对战/掉落）、日/周汇总、趋势图
- **数据依据**：全部事件（事件日志 `data/eventlog/*.jsonl` 已有持久化）
- **UI 建议**：横向时间轴 + 概览图表
- **优先级**：P1（成本低，复用已有日志）

### M16. 数据导出与分享 Export & Share
- **定位**：把数据带出去（对标原神 UIGF 生态）
- **内容**：宠物仓库导出 JSON/CSV/Excel、战报生成长图/链接、录制回放分享
- **数据依据**：各域快照 + 已有 `recording/`
- **UI 建议**：导出按钮 + 分享预览弹窗
- **优先级**：P1（社区传播的杠杆点）

## 4. 分期路线建议

| 期 | 目标 | 模块 | 验收标准 |
|---|---|---|---|
| **V1（立即）** | 把已有数据做透 | M1 概览、M2 宠物详情、M15 时间线基础、S5 | 宠物 160 只详情页可查；概览卡片有真实数字 |
| **V1.5（一次完整录制后）** | 验证事件域 | 用一次"打一场 PVE + 抓一只 + 开背包 + 打一场 PVP"的录制，验证 M4/M6/M7 帧 | 事件日志里能看到战斗回合/捕获概率/背包帧 |
| **V2** | 差异化爆发 | M4 对战观测、M6 捕获中心、M16 导出 | 战斗中实时看到回合流与捕获概率 |
| **V3** | 战报生态 | M5 战报复盘、M3 个体评估、M7/M8/M9 | PVP 打完出伤害统计报告 |

**关键前置**：V1.5 的"完整业务录制"是一次数据采集任务（不需要写新代码，只需开着监听玩一遍），它决定 V2 的排期。

## 5. UI/UX 设计要点（直接可用的设计输入）

### 5.1 信息架构建议

```
一级导航（侧栏或顶栏 Tab）
├── 概览 Dashboard          ← 首页，聚合卡片
├── 宠物 Pet                 ← 仓库列表 + 详情
├── 对战 Battle              ← 实时观测 + 历史战报
├── 收集 Collect             ← 图鉴 + 捕获中心 + 掉落
├── 世界 World               ← 背包 + 地图 + 商店/活动 + 任务
├── 社交 Social              ← 好友/串门/邮件
├── 工具 Tools               ← 导出/统计/时间线
└── 系统 System              ← 监听控制台 + 事件流 + 回放 + 设置（专家区）
```

### 5.2 三态设计（每个数据页必须处理）

| 状态 | 表现 | 文案要点 |
|---|---|---|
| **监听中** | 实时刷新，有新数据高亮/动效 | "登录后自动积累" |
| **离线/回放** | 展示上次会话数据，标注时间戳 | "数据来自 10-09 的会话" |
| **空态** | 引导性占位图 + 行动指引 | "开始监听并进入游戏，数据会自动出现" |

### 5.3 通用交互模式

- **列表-详情**（Master-Detail）：宠物/背包/任务/邮件共用一套列表组件；
- **实时流**（Live Feed）：对战/捕获/掉落共用事件卡片组件（时间戳 + 图标 + 摘要 + 可展开原始帧）；
- **统计图**：伤害占比（堆叠条）、胜率趋势（折线）、图鉴进度（环）；
- **悬浮 Overlay**（长期）：战斗中置顶小窗（参考 ACT），需游戏窗口化配合。

### 5.4 提醒/告警设计

- 应用内横幅（捕获概率、稀有出现、任务可领奖）
- 系统托盘通知（可选）
- 声音提示（可关）——参考 cactbot/WeakAuras 的触发器范式

## 6. 风险与合规定位（写进产品文案）

1. **只读原则**：不注入、不改包、不自动化操作——与 RocoPilot 类"辅助脚本"划清界限；
2. **不做交易估价/自动化**：市面空白但风险高（涉及经济系统），建议长期观望；
3. **隐私**：好友/聊天数据涉及他人，默认本地存储、不做云端上报；
4. **数据来源声明**：静态数据（图鉴/技能表）建议引用社区 Wiki 并标注来源，不重新发明。
