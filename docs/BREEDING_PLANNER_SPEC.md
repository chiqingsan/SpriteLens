实现路径：`domain/breeding_planner.py`（准入/评估）、`domain/breeding_solver.py`（搜索）、`domain/breeding_nature.py`（与家园共用性格分支）、`services/breeding_planner_service.py`（一致快照/取消/原子保存）、`view_models/breeding_planner_vm.py`、`web/breeding_planner.py` 及 Vue 页面/composable。`PetRepository.breeding_snapshot()` 将声音修正与宠物版本放在同一锁边界，声音写入失败不推进版本。

首版搜索是有限候选/格位上的确定顺序束搜索：通常最多64个搜索候选，保留锁定；单/双个体共同扩展，比较不用绿窝/绿窝入住父本或母本，按完整布局评估。候选筛查最多60000组或约1秒，布局评估最多4500次，总计算约3秒停止；束宽2，使用紧凑/分簇网格及锁位周边格。达到预算保留已评估方案，未完整筛查的目标不宣称库存无合格亲本。始终标为`bounded`，不宣称全局最优，也未提供继续加预算按钮。最多三套有实质差异的布局，平移/镜像同关系不凑数；存在有效配对时不拿空布局凑备选。当前有效布局作为搜索基线，有限网格改进未找到更好结果时保留较好的现有方案。

布局采用暖白主工作区＋360px目标侧栏；产物放在画布下方，避免设置与结果相互遮挡。窄窗上下排列，候选使用原生模态弹层；复用BreederCard、UiIcon、主题及本地奖牌图，不增加组件依赖。坐标或亲本变更后重评；加载保留内容。数据更新只标旧布局待评，重新规划才更换亲本。原方案在迭代比较时保留为对照；保存只存当前草稿，不保存候选方案全集。

以下章节继续描述产品规则及验收意图；真实游戏坐标校准、实际遗传范围和桌面WebView2验收仍开放，不因本地回归通过而宣告完成。界面参考与当前落地差异以上述实现说明为准。

## 1. 功能目标、入口与默认行为

2026-10-17用户决策已收口为 `1B、2B、3B、4A、5A、6A、7B`，本表优先于此前未确认的默认建议。技术搜索细节由实现者在这些产品约束内确定，不再向用户重复确认：

| 决策 | 已确认行为 |
| --- | --- |
| 1B | 繁育机会优先：先增加符合规划条件的有效母本，再比较目标性格支持质量；不把母本数冒充单位时间产量 |
| 2B | 同优先级目标先集中推进库存条件好的目标，不强制均摊；允许其他目标暂时缺位 |
| 3B | 用户启用迭代方案后，允许减少合格母本来覆盖更多目标，明确展示合格与迭代的取舍 |
| 4A | 遗传范围未知的近似候选可以作为方向参考参与规划，不宣称可达概率或最低遗传数值 |
| 5A | 自动迭代推荐只允许缺一类目标奖牌，性格状态独立展示 |
| 6A | 先展示近似候选，用户明确选择“生成迭代方案/用此亲本迭代”后才纳入求解，不自动带入 |
| 7B | 自选精灵默认“择优参与”，允许用户切到“全部参与” |

冲突优先序：基础/锁定硬约束 → 用户显式目标优先级 → 在用户准许的合格/迭代范围内覆盖更多目标（3B）→ 更多有效母本（1B）→ 同级集中库存优势目标（2B）→ 匹配质量等次级指标。扩大覆盖不等于要求均衡配额；迭代未被用户启用时不进入这套取舍。

### 1.1 完整用例

用户设置“喵喵蛋＋大块头＋婉转声＋急躁”，工具从当前账号已观察背包中选出亲本，决定使用多少普通窝、是否使用学院绿窝，生成摆位和全部配对连线。用户查看每个母本的可能产物、性格参考、奖牌支持、缺口，拖动/锁定/替换后重新分析。多个目标共用一份库存和窝位预算，不能分别计算后直接拼接。

只做本地规划和资料展示，不发送游戏摆窝、放入精灵或收蛋指令。结果中的“支持目标”表示符合本规划规则，不是承诺每颗蛋都获得目标特征。

### 1.2 两个入口，共用一个引擎

| 入口 | 用户输入 | 默认及结果 |
| --- | --- | --- |
| 按目标配窝 | 一个或多个普通可繁育蛋、每个蛋的奖牌/性格和优先级 | 从当前账号库存择优选亲本，生成数量、摆位、产物及缺口 |
| 自选精灵配窝 | 从当前账号选择若干实际个体 | 默认“择优参与”；选择有效子集、决定父母关系和摆位，推演可能产物并解释未采用个体 |

自选入口默认将所选精灵作为候选池，不要求全部使用；另提供“全部参与”，此模式不得偷偷丢弃不兼容个体。两入口各保留当前草稿；切换入口不清空另一份草稿，也不将目标结果直接当作另一模式的原始输入。

### 1.3 容量和数量

- 普通窝默认10个，用户可设置实际可用数量0～10；学院绿窝默认关闭，可设置有1个，总容量最多11。0个普通窝允许与1个绿窝共同形成不足2窝的提示状态，不生成配对。
- 默认数量是本次规划容量，不冒充从家园采集到了10/11窝。已有家园只能提供建议数量及观察来源，用户确认设置后才改变草稿。
- 一只精灵只占一个窝，一只母本可连多个父本，一只父本可连多个母本；不同个体即使同物种、同属性，也能分别参与。
- 可以使用少于容量的精灵。未用窝明确说明原因：无可用目标母本、无额外目标收益、资料待补、锁定限制或无法摆出有效连接。不用无关精灵填空。
- 自动配额枚举所有满足容量及锁定约束的公母数量，而不是固定5公5母。无产蛋速率公式时，推荐数量按目标支持和覆盖排序，不标注“每小时最多产蛋”。

### 1.4 目标编辑

每个目标包括 `goalId / eggKey / sizeMark / voiceMark / natureId / priority`：

- 蛋按稳定目录ID选择，显示蛋图、名称、蛋组及对应繁育物种。活动/剧情/自选蛋等不可由普通小窝直接获得的特殊版本不可作为普通目标；给出“来源不属于小窝”的原因。缺少可靠繁育映射的目录项保留“资料待补”，不能按同名猜测。
- 体型：不限/大块头/小不点三选一；声音：不限/婉转声/粗嗓门三选一。允许无奖牌、单奖牌或双奖牌目标，不允许同类互斥条件。
- 性格：不限或一个目录性格，覆盖完整性格目录。性格是产物目标，不是强制双亲同性格的筛选开关。
- 优先级：默认“普通”，可设“优先”。同优先级先集中推进库存条件更好的目标，不强制每个目标分到相同母本数；容量不够时其他目标可暂时无位并显示原因。不在第一版增加预计蛋数、小时产量或自定义分数权重。
- 完全相同目标合并；同一蛋不同奖牌/性格保留为不同目标。不因目标数大于母本容量而拒绝输入，返回当前方案未覆盖目标及原因。
- 修改目标、容量、模式后立即标记现有方案“待重新规划”，保留布局以便比较；点击生成才选择新亲本。不把旧结果继续标成匹配新目标。
- 按目标入口尚未添加目标、自选入口未选精灵时显示对应空态并禁用生成；不自动回退成蛋组全覆盖或替用户选一个目标。

## 2. 配对与产物计算规则

### 2.1 数据准入与身份

按 `(uid, gid)` 标识个体，禁止用名称、图鉴号、进化链或场景actorId替代。同账号库存和目录在同一次不可变计算输入中固定版本，忽略前台分页和列表筛选，读取该账号完整的已观察集合。

基础配对要求：两只真实可用个体、已知异性、共享有效蛋组。未知性别、不可繁育蛋组、试用/镜像个体不进入自动有效组合；资料未知与明确不可繁育分开。一个已知有效蛋组与另一个未知标签共存时，保留已知蛋组，不因未知标签整只排除；明确不可繁育标记与有效蛋组冲突时单列资料冲突，不猜测。

没有仓库完整性证据时写“根据当前已观察背包”。找不到个体表示“当前记录未找到”，不能据此断言用户没有。缺图只显示占位，不影响兼容性；缺性格不影响基本繁育；缺奖牌不补成目标奖牌。

母本是否对应目标蛋由现有 `EggCatalog` 及明确的物种/形态映射确定。进化后母本通过目录回到实际可繁育蛋，不能因显示名称不同漏掉；同名地区形态不擅自合并，映射冲突保持未知。

### 2.2 用户确认的双奖牌宽容规则

规则ID：`planner-dual-mark-v1`。本轮默认把“同蛋组双奖牌”解释为**父母双方都具有目标要求的那一组体型牌和声音牌**，允许跨物种、不同性格、不同身高/体重原值；不额外要求±100dB、满体重或双亲同性格。不是任意两种不同双牌都合并成用户指定双牌。

设 `R(t)` 为目标要求的奖牌集合，`marks(p)` 为某个亲本已有结构化标记：

```text
基础兼容(m,f) = 同账号 ∧ 异性 ∧ 有效蛋组交集非空
共有奖牌(m,f) = marks(m) ∩ marks(f)
奖牌支持(m,f,t) = 基础兼容(m,f) ∧ R(t) ⊆ 共有奖牌(m,f)
物种支持(f,t) = 母本对应的普通繁育蛋 == 目标蛋
目标奖牌有效边(m,f,t) = 奖牌支持(m,f,t) ∧ 物种支持(f,t)
```

| 父本 / 母本 | 大块头＋婉转声目标的处理 |
| --- | --- |
| 大婉 / 大婉，同蛋组、不同物种、不同性格 | 有效组合；母本物种决定蛋，性格独立排序 |
| 大婉 / 大婉，96dB与100dB、体重不同 | 只要有效标记成立就接受，不追加极值门槛 |
| 大婉 / 大粗 | 共有“大块头”；支持大块头单牌目标，不支持大婉双牌目标 |
| 大婉 / 小婉 | 共有“婉转声”；支持声音单牌目标，不支持大婉双牌目标 |
| 大块头单牌 / 婉转声单牌 | 不把父母牌取并集，不列为大婉有效组合 |
| 一方牌未知 / 大婉 | 基本兼容可以保留；奖牌支持未知，不算双牌目标已支持 |

`marks(p)` 复用 `pet_marks` 的佩戴优先/数值参考口径及 `source`，两类已有标记默认都参与，以保持与背包一致和候选宽容度；结果明示参考来源，不在本功能另设一套极值阈值。只有满身高、或历史获得过某奖牌，不新增当前体型标记。不改写亲本原始数据。

上述规则把共有双牌作为规划上的有效产物标签，不建立奖牌遗传百分比。普通无奖牌目标的 `R(t)` 为空，全部基本兼容边可支持；单牌目标仅要求双方共有该牌。学院窝不跳过奖牌检查。

### 2.3 性格与学院绿窝

普通窝沿用现有工具参考：父本30%＋母本30%＋随机40%。双亲不同性格允许配对，双方都没有目标性格也允许，只显示“目标性格需随机筛选”；未知性格的亲本份额进入未知，不当成随机或已知不匹配。

例：急躁父本＋非急躁母本，急躁有30%的已知亲本贡献；双方急躁为60%已知贡献。随机40%仍可能命中急躁，不能写成“最终成功率30%/60%”或剩余部分排除急躁。

学院绿窝容量只有1，自动比较不用、放父本、放母本三种情况。性格参考沿用现有家园逐父本分支：母本在学院窝时，该边跟随母本；父本在学院窝时，该边跟随父本；都不在时使用普通窝。学院亲本性格缺失则该边参考为未知。单绿窝使“双亲同时在学院窝”在本规划中不可构造。

这里的100%属于现有工具模型，不作为实测保证。绿窝只影响与其入住精灵实际相连的配对，不使其他普通窝的全部产物锁性格。修改后性格缺少原始证据时可按当前记录参与参考并标注来源不确定，不因缺少修改历史排除整个候选；若已知不遗传当前改后性格，不能把它计入已知遗传贡献。

### 2.4 全部父本、干扰与条件参考

对每个母本，从最终布局得到全部范围内、基本兼容的父本集合 `F(f)`，包括不符合当前目标奖牌/性格的父本。不能只显示推荐父本而隐藏其他实际候选。

- 先计算每条父母边的共有奖牌和性格分布，再汇总到母本；不先平均全体父本分贝/体重后生成奖牌。
- 多父本参考沿用等权假设，每条边权重 `1 / |F(f)|`；保留该假设及未知份额。不是已验证的真实父本选取概率。
- 对目标t，返回符合目标奖牌的父本数、父本总数、其已知性格贡献及不匹配父本列表。若显示“只看奖牌匹配父本”的性格分布，必须标成条件分布；全体父本分布也保留，不能把条件结果冒充总结果。
- 定义“干扰”为兼容且在范围内，但不满足该母本主目标的奖牌条件，或降低目标性格参考支持的父本；干扰是相对目标的概念，不能直接删除这条真实模拟连线。
- 在目标覆盖、有效母本数量和库存集中指标相同时，优先让目标母本全部可能父本都满足目标奖牌；机会更多但含干扰的方案允许参与比较并标为部分方案，明确“2/3父本支持目标”，而不是声称该母本产出全部符合目标。
- 不同母本独立汇总，同名父本按实例区分。同一父本连接多个母本不表示它同时产生多份独立计时产量；连线数不等于蛋数。

给实现者的汇总口径：令 `q(m,f,n)` 为逐边对目标性格n的已知贡献（普通窝为两亲本各0.3，学院分支为对应亲本1.0；未知份额另存），`b(m,f,t)` 为该边奖牌支持目标t时1，否则0，则：

```text
母本全部父本的已知性格贡献 A(f,n) = Σ q(m,f,n) / |F(f)|
目标奖牌父本占比 B(f,t) = Σ b(m,f,t) / |F(f)|
目标相关的已知贡献 K(f,t,n) = Σ [b(m,f,t) × q(m,f,n)] / |F(f)|
```

排序使用K评估目标性格的已知亲本支持，不把不支持奖牌的父本贡献计入该目标；展示同时保留A和B。K仍依赖规划双牌与父本等权假设，不能标成真实“目标蛋成功率”。`F(f)`为空时这三项为null；没有目标性格时K不计算。逐边未知奖牌不按确认支持计分，输出单列未知来源，不能解读为已证不可能。

### 2.5 摆位规则与家园事实边界

当前项目 `domain/home_breeding.py` 使用同楼层、原始坐标差除以40、边缘偏移4，再以欧氏距离≤10推导候选；公开计算器采用2×2占地、中心曼哈顿距离≤5。两套坐标/距离规则尚未证明等价，不能混算。

首版模拟画布明确采用 `community-grid-v1`：普通/学院窝都按2×2占地，中心坐标以0.5格吸附；同一平面上满足 `abs(dx)+abs(dy) ≤ 5` 的异性窝再检查蛋组。不叠加另一工具的切比雪夫限制，也不把这里的格直接当成真实家园原始坐标。

- 两窝内部相交算重叠，边缘贴合允许。坐标是小窝中心，不是头像左上角；旋转画布仅改变视图，不改变关系。
- 单层模拟工作面，可平移、缩放和自动适配，不硬编码7×7为玩家家园真实面积。求解用有限候选格位/布局模板，结果说明是该模拟规则下的建议。
- 正式宣称“可直接照摆”前，用真实游戏验证贴边、斜角、半格、阈值边界与跨楼层；确认坐标比例和距离规则后升级固定 `geometryRuleVersion`，重评旧计划，不静默切换算法。
- 本期不恢复家园页已取消的位置图，不导入真实家园坐标作为模拟格位；智能配窝的编辑画布是新的本地方案。实际家园配对证据与模拟连线分别展示，永不以模拟覆盖场景 `layEggCouples`。

### 2.6 生蛋占用与后代范围

默认模式为“长期摆窝方案”，母本有未取走的蛋不排除亲本，但显示“取蛋后继续”；这种状态只在实例和窝位证据可确认时展示。没有真实占用证据时为未知。与旧调研中“未取蛋母本不可用”相比，此处只限制即时生蛋，不限制长期规划。

输出区分：普通蛋物种、按规划规则支持的奖牌、性格参考、资料未知。天分、个体资质、特长、异色/炫彩精确概率不作为首版评分项；已有亲本数据可在详情查看。特殊蛋不冒充普通配种结果。不输出预计收蛋时刻、每天枚数或保证出蛋代数。

### 2.7 无合格组合时的迭代候选

#### 分层及触发

每个目标先正常搜索合格组合。若在当前已观察背包内没有满足奖牌要求的父母组合，自动展开“迭代候选”；多个目标中只对奖牌缺口目标补充，不降低“合格”的判定标准。用户主动启用迭代后，允许重新调配未锁定合格母本的数量以覆盖更多目标，不能默认把近似当合格或自动带入。因为搜索预算不足、容量争用或摆位未找到而缺方案时，应分别说明原因，不能误说库存无合格亲本。

三类结果独立：`exact`为符合现有目标奖牌规则的合格组合（性格状态另列），`iterative`为明确缺少目标标记但有已知原始数据可作培养参考的近似组合，`unknown`为缺数据不能判断接近程度。`exact`不等于必出，`iterative`不计入合格目标数。

迭代候选仍须同账号、异性、共享有效蛋组、母本产目标蛋。首版自动推荐“只缺一类目标奖牌”的组合：另一类目标牌在双方都成立，缺失类在一方有目标牌，另一方有可核对的原始值；父本和母本都可以是待迭代方。两类目标牌同时欠缺、对立奖牌组合和资料未知进入次要方向参考，不自动生成主推荐。不能把缺声音误标为已知声音低，也不能只因性格相同就认为声体接近。

#### 原始声音、目标区间与遗传范围

2026-10-17用户澄清：示例是父本原始声音**95dB**，不是95%刻度。母本已有婉转声，父本没有婉转声但95dB接近目标，可能通过生蛋遗传范围中的浮动或后续筛选得到符合要求的子代；体重按相同思路判断。本节以此为当前设计，取代此前围绕95%换算和纯均值下限的候选判定建议。

候选声音主要显示原始整数dB；现有家园百分比只是可选辅助展示，不改全项目刻度换算，也不按四舍五入的百分比判断达标。当前 `pet_marks.voice_mark` 用96～100dB作婉转声数值参考、−100～−96dB作粗嗓门参考，对应佩戴牌仍优先；这些是当前工具标记线，不等于已经核实的游戏遗传边界。

判定需要分别取得：目标子代标记区间、双方原始声音、双方有效体重/身高及物种、该父母组合对应的子代遗传取值范围和证据来源。声音近似看子代声音范围是否可能进入目标区间；体型近似看子代物种的体型/体重范围与获牌条件，不能仅比较父母原始数值大小。

```text
参考可达 = 已核对模型给出的子代遗传范围 与 目标获牌区间 存在交集
方向接近 = 亲本原始数值接近目标，但遗传范围尚未核实
本代范围不覆盖 = 已核对模型的子代范围与目标区间无交集
```

声音和体型各自有范围交集，不自动证明同一子代可以同时满足双牌；有联合分布/约束证据时才说明联合可达，否则标注“双牌同时出现待确认”。范围上界/下界能达到目标也不代表成功率高，不把两个未知概率相乘。

现有 `trunc((v1+v2)/2)` 只是单点均值参考，没有随机浮动或完整遗传范围，不能作为近似候选的准入/排除依据。均值未越线或纯均值回交停滞，都不能据此判定游戏内不可达；均值越线也不能升级为合格或保证出牌。不再把92/93/94dB等纯均值反算值作为推荐最低分贝。

#### 用户示例及迭代判定

目标是喵喵大婉，母本已有大婉、父本只有大块头：

- 母本大婉、父本只有大块头且原始95dB：保留为“迭代候选”，说明双方已支持体型、父本声音接近目标但尚无婉转声。遗传范围已核实时判断是否覆盖目标；未核实时显示“声音接近，遗传范围待验证”，不能拒绝这只候选或写成已经能出大婉。
- 母本96dB、父本95dB：即使现有均值向零取整低于96dB，也不能排除随机遗传范围进入目标的可能；真实范围未知时仅作方向参考。
- 母本100dB、父本95dB：均值97dB可以作为辅助数值，但不据此认定单代一定出牌，也不将父本标成合格大婉。
- 母本只有佩戴婉转声、原始声音未知：保留实际牌；父本95dB仍可显示接近方向，组合的遗传范围单列待补，不把母本补成100dB。

接近度按原始值到目标参考区间的有向距离排序，不能按绝对值把粗嗓门候选当作婉转声近似。分别保留“亲本差多少”“子代范围是否覆盖”“模型证据是否充分”；原始数值已知但遗传范围未知仍属于迭代方向候选，不与原始数据缺失混为一类。

不设置统一“最低90/92/95dB”硬过滤。真实最低候选分贝必须由配偶数值、遗传浮动范围、取整/限幅和获牌条件共同反推；模型缺失时保持未知。首版不做完整多代求解、不报预计代数或必出时间，只说明下一步筛选方向；本代范围不覆盖也不等于已证明多代培养不可行。只有完整证据才可排除相应路径，不用纯均值回交模拟替代它。

#### 体型、实际子代与版本

缺体型时按同一套“实际亲本未达标、子代遗传范围可能达标”的逻辑显示候选。例如一方已有大块头，另一方没有大块头但体重接近该物种目标区域，仍可展示培养方向，并保留双方已有声音牌。声音用原始dB，体型同时显示原始体重及本物种范围位置；跨物种必须经明确的后代物种映射/归一遗传规则比较，不平均不同物种原始千克数，也不凭归一百分比均值宣称子代可获牌。

满身高不补体型牌；体重近线不自动补大块头/小不点。如果获牌还涉及身高等联合条件，需要一起检查。体重遗传函数、浮动范围或获牌条件尚不清楚时保留“体重接近，遗传范围待验证”，不虚构允许的最低体重、单代可达或概率。

实际孵出并采集子代后，用户可选择用该真实个体替换待迭代亲本，重新检查性别、蛋组、母本映射、标记及性格。只有新的组合实际满足原规则后才从迭代升级为合格；不生成虚构gid，不把参考子代直接加入背包、画布或双牌产线配齐统计。

`voice-parent-mean-v1`仅作为现有单点参考模型保留，不充当范围遗传模型。2026-10-17检索到作者Ya_星河的[声体继承与迭代视频](https://www.bilibili.com/video/BV19kj36cEcx/)，但未取得可核验字幕/公式正文；[玩家迭代记录](https://www.taptap.cn/moment/815502902587034290)只能支持培养方向，未提供可用的声音分布。不得从视频标题推断浮动幅度。未来核实实际遗传函数时，必须明确其输入单位、浮动作用位置、取整顺序、上下界、分布、限幅及体型的物种换算，再记录来源/样本和更新规则版本；不预设真实函数一定是“均值后加ε”。

## 3. 规划引擎、数量分配与输出

### 3.1 候选构建

1. 按账号固定库存、目录、手动声音、规则版本；取得候选原始字段与标记来源，列出被排除/待补原因。
2. 按目标反查所有可产该蛋的母本；父本搜索全部共享蛋组的物种，不限同种/同链。自选模式只使用所选实例，不擅自补入库中其他个体。
3. 建立基本兼容图，以及逐目标的奖牌/性格支持；不能直接复用筛选页默认 `same_nature=true`，也不能照搬产线页的同性格准入限制。
4. 同性别、共享蛋组、实际繁育蛋、目标奖牌、性格及来源不确定性、学院资格、锁定约束完全等价的个体可分组减少搜索，但保留数量和所有gid；不同个体不能被去重成一只。每组只需保留不超过总窝数的可选代表，必选/锁定实例始终单独保留。
5. 对尚无奖牌合格组合的目标另建迭代候选集合；此集合的等价分组必须包含缺失项和有效原始分贝/体型位置，不能将90dB和95dB等不同培养价值个体合并。已知数值缺目标牌、未知数值和合格牌分开，不能靠放宽同一个过滤器混出“合格”结果。

### 3.2 联合搜索

- 枚举可行公母数量、绿窝分配和候选子集；按目标覆盖构建初始解，优先保留只有少数父本可支持的母本，不把启发式唯一依赖当作不可解锁的游戏规则。
- 对候选子集求摆位；发现无有效连接、非目标父本干扰、锁定位置不适配时返回亲本/配额阶段尝试其他组合。不能先固定“最佳10只”再用无法摆出的图交付。
- 小输入可用分支限界穷举；较大输入用贪心初始解＋单/双个体交换＋位置交换改进。每一步都调用同一个完整方案评估函数。
- 搜索采用固定遍历、稳定破同分和可重复的节点预算。达到预算就返回已验证的当前较优结果，标记 `bounded`；没有搜索证明时不写“全局最优”。仅在候选实例、配额和有限格位都完整枚举后，才标记“当前候选空间最优”。
- 若未找到有效方案且搜索未穷尽，显示“本次搜索未找到”，不能输出数学上的无解。继续计算可以加大本次节点预算，无需新增运行依赖或通用任务平台。
- 最多保留3套有实质差别的方案，按不同亲本、公母比例或连接关系去重；平移/镜像产生的等价布局不凑数。没有第二套就只显示一套。

### 3.3 默认排序：可解释的顺序比较

硬条件先于所有收益：同账号、实例唯一、容量、无重叠、必选和位置锁定必须成立；必须参与但无有效关系时仅能输出部分方案，不称为完整成功。后续依次比较以下指标，不将其混成用户看不懂的固定加权总分：

1. 先比较“优先”级目标的覆盖数和有效主目标母本总数，再比较“普通”级对应两项。覆盖包括合格支持和用户已明确准许的迭代支持，按目标去重；迭代未准许时只算合格。符合原奖牌规则的才计“合格支持”，迭代另计“迭代覆盖”，不能将合并覆盖数写成合格数。同一母本可支持多个可能结果，但仍只计一个生产位。性格需随机/未知不阻止基本覆盖，状态单列。
2. 同级覆盖与有效母本总数相同时，按库存优势目标的顺序比较主目标母本分配向量，不再升序比较最少配额。库存优势以该目标候选中的可用母本数、兼容父本支持广度、已保留目标牌和性格支持依次排序，明确优先级仍高于库存优势；同分用稳定目标键破同分。候选范围仅包括本次允许的实例及迭代授权，不能把尚未准许的近似库存算成优势。默认允许优势目标3＋另一目标1优先于2＋2，不要求公平分摊。
3. 上述指标相同，再比较合格主目标母本数量、全部父本都满足目标奖牌的覆盖数、目标已知性格贡献K总和及目标奖牌父本占比B，偏好更少干扰。性格不限的目标跳过K，不凭空得到100%优势；随机/未知不作为已知贡献。迭代方向接近不改变K/B的合格判定。
4. 再比较迭代候选缺失项更少、已有范围证据更充分、原始数值更接近目标及性格支持；遗传范围未知的方向参考按4A允许参与，但明确不代表成功概率。
5. 同收益时优先更少未连接/资料不明个体，再优先使用更少额外父本/窝位；最后比较对现有草稿更少替换和移动。首次生成无移动成本，按稳定目录号、gid和规范化位置破同分。

“有效主目标母本”指存在目标奖牌有效边，或存在用户准许的迭代边，并主分配给该目标的已放置母本。每个母本最多分配一个 `primaryGoalId`，母本资源和数量收益不能重复计给多个目标；目标可行性覆盖则允许共享。例如同一喵喵母本可能支持急躁、胆小两个目标，这两个目标都显示可尝试，同时提示“共享1个母本，并非2个独立生产位”。目标输出分别给出合格/迭代的 `supportMotherCount` 和 `primaryMotherCount`，全局母本数按gid去重。若该母本对主目标已属合格，不再重复计为迭代。用户可改主目标并重评，不复制该母本。

本排序优化目标支持及机会覆盖，不证明真实单位时间产量最大。为展示取舍，可在有合适候选时附带一套公母数量较均衡的可行方案，标注覆盖变化；不默认认定1:1或一公多母必然更快。不为填满窝位牺牲更靠前的目标指标。

迭代候选先独立展示，只有用户点击“生成迭代方案/用此亲本迭代”后才进入新的联合搜索；本次准许范围随草稿保存，移除/关闭该选择后再重评。自动推荐仍只允许缺一类奖牌。未知遗传范围的候选可参与，纯均值可达/停滞不作为范围证据，也不令该边的 `b(m,f,t)` 变成1，K/B和合格统计保持原规则。

按3B允许减少未锁定合格母本，换取更多目标的合格或迭代覆盖；原有方案保留为可返回备选，新方案展示“目标A合格母本3→2，新增目标B迭代母本1”等具体变化，不设置“合格母本数不得减少”的隐藏约束。不得改变锁定实例/位置，也不得把更多迭代覆盖包装成更多合格覆盖；是否更换当前方案仍由用户选择。仅查看候选不构成带入准许。

排序验收示例：同优先级同覆盖下，4只较弱目标性格支持的有效母本优先于3只较强支持的母本（1B）；母本总数与覆盖相同时优先库存优势目标3＋1而非强制2＋2（2B）；已启用迭代时，目标A合格母本由3减为2、换得目标B迭代母本1，覆盖从1个增为2个，可优先于原方案（3B）。这些是规划排序，不是实际产蛋速率/成功率结论。

### 3.4 自选精灵模式

- “全部参与”：超过总容量时保留选择并提示减少选择/改择优参与，不能自动截取前11只。无父本、无母本、未知性别、锁定冲突逐项列明；有部分有效组合时仍可给出部分布局和未连接精灵。
- “择优参与”（默认）：先优化参与有效关系的母本数，再比较被覆盖的不同普通蛋种数量、父母共有奖牌完整度和性格支持，最后比较较少无收益父本和较少移动。返回未选中候选及原因；不把无共有奖牌的基本兼容边判成不可生蛋。
- “全部参与”的实例集合固定，优化其有效母本/父本接入数和产物支持；没有目标时不因某只个体奖牌较少而移除。
- 每个母本展示全部兼容父本及逐边产物奖牌，例如既可能支持“大婉”也可能只支持“婉”；不从不同父本各取一个牌合成一个不存在的结果。
- 自选集合中有接近阈值的亲本时，可以附加迭代参考，但不自动从库存补入锚定亲本、不改所选集合；实际共有奖牌与可能培养方向分行显示。
- 同种蛋按 `eggKey` 汇总母本数量，展开后保留每个母本的性格参考和奖牌差异。无目标时不合并成“全都是双牌蛋”或无依据的综合概率。

### 3.5 无解、部分结果和替换

未覆盖原因按实际链路区分：无已观察目标母本、无兼容父本、目标奖牌不满足、性格仅随机/未知、容量竞争、实例被其他主目标使用、必选限制、锁定位置超距、资料冲突、布局搜索尚未找到。性格需随机筛选不是基本配种无解。

支持局部替换：展示备选精灵、替换后的完整连接/目标得失，再确认。替换只改变该实例所在窝，其他个体/位置不自动重排；导致冲突时保留预览，允许调整或取消。点击“重新规划”才重新选择未锁定个体和位置。

## 4. 页面布局与操作

### 4.1 信息架构

沿用项目暖白卡片、主题变量、本地奖牌/性格标签、性别描边和已有弹层，不引入新UI库。页面只有紧凑工具条、主画布、右侧设置/结果共享栏，避免叠加多层说明区。

```text
工具条：按目标配窝 / 自选精灵 ｜普通窝数量｜学院绿窝｜生成方案｜保存
方案条：方案1 / 方案2 / 方案3｜公母及使用窝位摘要｜撤销/重做/适配
主区：可拖动的小窝布局、全部兼容连线、空位/候选托盘
右栏：目标或精灵设置 / 产出与缺口 / 当前选中窝详情
```

右栏桌面固定360px，沿用项目可用宽度规则；窄窗口改为可切换面板/抽屉，主画布可平移，不把11张卡强行缩成不可读文字。画布和结果各自滚动，顶部操作固定。结果首次生成后进入结果页签，目标仍可随时编辑。

### 4.2 设置与结果卡

- 目标选择器搜索名称/图鉴号/蛋组，用现有蛋图和物种目录；选中目标逐行设置奖牌、性格、优先级、删除。重复目标提示已合并。
- 精灵选择器复用背包卡片信息，按父/母和条件筛选，清楚展示“已选”与个体详情入口；数量来自真实选中gid，分页不丢选择。
- 窝卡显示编号、头像、名称、性别、性格和两类标记；学院窝用现有主题强调并加文字，不只靠颜色。图像保留透明区域，不裁切重绘。
- 摘要显示“已用8/10窝，2公6母，覆盖2/3目标（合格1、迭代1）”；覆盖含用户准许的迭代时必须拆分，不把两类都称合格。结果另列性格支持和未知。空余、未采用及不匹配原因放在对应目标/个体处，不铺长篇固定说明。
- 点母本显示蛋、主目标、全部父本、共有奖牌、性格参考和不符合目标的连线；点父本高亮它连接的母本。未选中时弱化连线，悬停/选中后突出，避免线条压住名称。
- “未取蛋”是带来源的即时状态，不作为长期计划空位；没有来源时不显示猜测的生产状态。规划结果不预先写入实际蛋仓或改变产线配齐数。

### 4.3 拖动、锁定与重评

1. 拖动小窝按0.5格吸附，学院窝类型随窝移动；拖动精灵到另一窝是交换/换窝，不是把绿窝属性复制给该精灵。
2. 重叠时显示无效落点，松手回到上一有效位置；超距允许落下，但结果标明连接减少/目标部分失效，用户仍可继续调整。
3. 浏览器只即时绘制位移、吸附和重叠预览；配对与后代计算由Python权威评估。松手提交整份布局，返回前显示“正在重评”，不沿用旧线冒充新关系；连续拖动只采纳最新草稿修订号的结果。
4. 拖动不触发全局亲本重选。原方案下的调整形成“已调整”草稿；支持恢复该方案、撤销/重做以及明确的“重新规划”。编辑后保留当前方案身份，不在后台悄悄切换到方案1。
5. 两种锁：锁定参与（重算必须保留实例）和锁定位置（保留实例、窝类型和坐标）；后者包含前者。锁定不会跳过性别、奖牌或基础兼容检查。
6. 绿窝关闭、容量减少时，如果超容量或绿窝内有锁定个体，保留旧方案并列出冲突；用户解除冲突后重算，不静默删除锁。无锁定时由新方案决定是否不用绿窝。
7. 替换/移出/绿窝入住变化同样重评全部母本，主目标可以手动更改。删除目标后释放相关主目标分配，但不直接删除画布精灵。

提供点击“移动到窝位”、方向键移动和Enter确认作为拖动替代；Esc取消、锁按钮 `aria-pressed`、焦点恢复遵循现有弹层。普通文字不可选，输入正常可编辑。

### 4.4 状态稳定与保存

- 生成/刷新期间保留现有卡片、结果栏尺寸、固定文案和刷新图标；操作反馈用固定状态槽。旧方案标“计算前结果”，不清空全页制造闪动。
- 目标修改用草稿修订号，库存更新用快照版本；它们独立。结果绑定两者，旧响应不得覆盖新草稿。
- 默认不因采集到新精灵自动重排。提示“背包已更新，可重新评估”，先重评旧个体，再由用户决定重新规划。
- 按账号、入口保存各一份草稿，用户点击“保存方案”才持久化；离页保留会话草稿，未保存时明确提示。每个入口保存实际gid、坐标、绿窝分配、目标、锁、已准许迭代组合和规则版本，而不是只保存排序条件。
- 恢复时按gid重新关联并评估，不改选父本。缺失实例保留占位与说明；规则/库存变化后标记待评估，用户显式重算才替换。
- 保存失败保留全部编辑并提供重试，不显示保存成功。撤销历史只在会话内保存；不在首版引入计划库、多方案收藏管理或跨账号合并。

### 4.5 合格、迭代、未知的明显视觉区别

| 类别 | 卡片及文字 | 奖牌与数值 | 统计与操作 |
| --- | --- | --- | --- |
| 合格组合 | 实线边框、现有主题选中样式，文字“奖牌匹配” | 只画亲本已有标记 | 计合格目标，性格支持单列 |
| 迭代候选 | 琥珀弱底＋虚线边框＋工具图标，始终显示“迭代候选” | 已有大块头正常显示，缺婉转声以空位及“待培养”文字显示；主数值为父本95dB、距当前工具参考线1dB，并显示遗传范围覆盖状态 | 不计合格；按钮“生成迭代方案”或“用此亲本迭代” |
| 资料待补 | 中性边框＋问号图标，文字“资料不足” | 未知写“—”，不画已获目标奖牌 | 不计接近度，提供既有详情/手动分贝入口 |

迭代候选在未覆盖目标下自动展开，卡片列表先合格、再迭代、再未知，互不混排；没有合格时展示“暂无合格组合，以下可作迭代参考”，而不是空白页。用 `--amber` 等现有语义变量实现，三主题均不依赖单一颜色区分；不把正常候选置灰成不可点，不使用danger表现“尚未达标”。

示例卡片显示“父本95dB，尚缺婉转声；母本已有婉转声”。“距当前参考线1dB”只是父本原始值到工具标记线的差距，不是子代成功率；下面单列“遗传范围支持/范围待验证”。体重候选显示真实体重、物种范围位置及待培养体型牌。迭代缺失奖牌不能使用完整彩色已获样式，原有详情保持真实标记状态。

加入画布后，待迭代个体保留琥珀虚线标记；目标结果显示“合格0组 · 迭代1组”，方案标题标“含迭代候选”。相对于选中目标，合格连线实线，迭代关系琥珀虚线，其他基本兼容关系弱线仍保留；所有父本照常参与干扰/性格汇总。选中、锁定、保存或切换方案都不能抹掉迭代标记。

只缺性格而奖牌已合格的组合继续归合格奖牌区，并显示“性格需筛选/待确认”；不把声音迭代和性格随机机会混为一个接近度。数值/规则更新后重新分类，用户手动录入有效分贝只改变该账号原有声音数据并按来源重评，不能通过勾选“已达标”覆盖判断。

### 5.2 最小契约

建议鉴权API：GET `/api/breeding-planner/context`（目录/容量建议/快照事实），GET `/api/breeding-planner/candidates`（分页候选），POST `/api/breeding-planner/solve`（生成方案），POST `/api/breeding-planner/evaluate`（重评布局），GET/PUT `/api/breeding-planner/draft`（读取/保存当前入口草稿）。现用接口与命名见上方“当前实现”；本段保留最初契约提议。

```text
输入：uid, inputVersions, ruleVersion, geometryRuleVersion, draftRevision,
      mode(targets/selected), goals[], selectedGids[], participation(all/best，默认best),
      approvedIterationPairs[{goalId,maleGid,femaleGid}],
      ordinaryNestCount, hasAcademyNest, locks[], currentLayout[]

版本：当前实现 version（宠物与手动声音共用）+ catalog_version
      若参与家园状态展示，再带homeVersion和source；字段复用现有版本来源

方案：planId, planKind(exact/iterative/mixed), placements[{slotId, kind, gid, x, y, primaryGoalId, locks}],
      edges[{maleGid, femaleGid, sharedGroups, sharedMarks, targetMatches,
             natureReference, reasons}],
      mothers[{femaleGid, eggKey, fatherGids, perFatherOutcomes,
               allFatherNatureReference, conditionalTargetReferences}],
      goalResults[], iterationCandidates[], unusedCandidates[], gaps[], metrics, assumptions

迭代项：targetId, maleGid, femaleGid, matchKind(exact/iterative/unknown),
        missingMarks[], preservedMarks[], missingParent, candidateVoice,
        anchorVoice, voiceSources, parentGapDb, meanReference(optional),
        parentMeasurements, offspringSpeciesId,
        inheritanceReference{voiceRange, offspringSizeRange, jointSupport,
                             status(range_supported/near_unverified/range_excluded),
                             evidenceBasis, modelVersion},
        minimumCandidateVoice|null, minimumCandidateWeight|null

响应：uid, inputVersions, ruleVersion, geometryRuleVersion, draftRevision,
      status(ready/partial/no_plan/invalid), freshness(current/stale),
      searchStatus(exhaustive/bounded/not_run), plans[], issues[]
```

当前实现与上述提议的差异（2026-10-18核对）：`searchStatus`只产生`bounded`（达到预算并保留已评估方案）与`not_run`（evaluate分支）；束宽2的剪枝不构成穷尽证明，`exhaustive`与“当前候选空间最优”仍只是设计意图，未实现，前端`parseResult`白名单（`frontend/src/types/breedingPlanner.ts`）同步只接受这两个值，补`exhaustive`需前后端同改。迭代项现用字段为`key/goal_id/male/female/kind/missing_marks/missing_parent/candidate_voice/candidate_weight_ratio/candidate_weight/candidate_species/anchor_voice/gap/approved/has_exact/evidence`；上文`inheritanceReference`、`minimumCandidateVoice`、`minimumCandidateWeight`、`preservedMarks`等遗传范围字段尚未实现。`planKind`与`genomeSurfaces`未实现，评分只输出排序所需的启发式`score`与`metrics`。

目标奖牌匹配用状态/集合，不虚构概率；未知参考用null及reason，不用0代替。没有父本的母本只有物种候选，没有性格/奖牌结果。所有返回保留结构化标记来源与逐边依据，前端不解析解释文字制造标签。

`approvedIterationPairs`初始为空。单卡“用此亲本迭代”只准许该目标的该组合；“生成迭代方案”提交用户已选择的候选组合集合。后台仍重验账号、实例和只缺一类奖牌的条件；不能仅凭接口标记将任意组合当成近似有效，也不将列表中尚未选择的其他候选带入。

`ready`要求布局有效、所有必选均有基本兼容连线；按目标模式还需每个目标至少有一只支持母本，该母本的全部父本满足目标奖牌，指定性格有已知亲本贡献。允许目标共享母本，但共享关系必须明确。它表示规划参考就绪，不保证实际产物。只有随机性格机会、未知资料、目标未覆盖、干扰或必选未连接时为 `partial`，即使已用满窝也不能ready。没有任何有效基本配对为 `no_plan`；非法参数/超容量/重叠/无法满足的硬锁为 `invalid`。允许带诊断布局返回partial/no_plan；freshness和searchStatus另列，不用ready掩盖旧数据或搜索未穷尽。自选模式无指定目标，只要全部必须参与的实例接入、布局有效即可ready，未知产物字段仍保留未知。

只有迭代候选而未纳入画布时，主目标可为no_plan并同时返回非空iterationCandidates；采用后的迭代方案按目标状态仍为partial，不能因为均值或遗传范围覆盖目标就ready。范围或候选最低值无证据时null，已知亲本95dB但范围未知返回near_unverified；不能复用均值反算填充最低值。粗嗓门/小不点需要上界语义时返回对应maximum字段，不误写最低值。范围无交集指本代模型不覆盖，不代表多代路径已排除。

gid统一沿用筛选配对DTO的十进制字符串；UID/目录ID沿用现有契约，场景actorId/guid等64位字段为字符串，不做全局数字转字符串。计划编号和输入修订号只是本地关联，不是游戏实例ID。

### 5.3 失败、并发与数据变更

| 情况 | 处理 |
| --- | --- |
| 非法容量、相互矛盾奖牌、重复实例、非法坐标 | 400及对应字段原因，保留草稿 |
| 必选超过容量、锁位冲突 | 返回invalid及冲突清单，不静默放宽用户约束 |
| 基础数据缺失、候选不足 | 返回partial/no_plan及资料/缺口，能算的目标照常展示 |
| 目录资源整体不可用 | 明确功能暂不可算，不伪造空库存 |
| 输入版本落后、切号 | 版本冲突要求刷新；旧账号结果不得提交为当前方案 |
| 重叠布局提交 | invalid并指出窝位，服务端不自动挪动 |
| 拖动后超距/目标受干扰 | 返回完整评估和partial；不认作接口错误 |
| 搜索预算用尽 | 有有效解返回较优方案和bounded；无有效解表示未找到，不证明无解 |
| 计算异常/取消 | 具体错误或取消状态，旧方案保留，不吞错返回ready |
| 持久化失败/存档版本不支持 | 保留会话草稿，显示失败或不支持，不覆盖原存档 |

计算在服务线程执行，不能阻塞aiohttp循环或Vue主线程。前端取消请求、核对uid/版本/修订号；CPU搜索按节点批次检查取消和预算，断开请求不留下无限搜索。新请求取代旧请求时停止旧搜索，不启动无界并行任务；不新建常驻任务平台。

同账号宠物更新、手动声音或目录变化使原方案stale；切号直接切换账号草稿，取消在途计算/保存，旧响应丢弃。仅家园即时占用变化可以只刷新状态，不重选亲本。库存来源为历史时允许离线模拟，但明确历史事实；既有有效空库存不可被旧缓存悄悄补回。

持续状态以ROADMAP F04-U5为准，各步都保留可观察输入/结果，不因某个模块完成宣布整个功能完成：

| 切片 | 交付范围 | 本步验收重点 |

### 6.3 首版边界与后续

首版完整包含两个入口、宽容双奖牌、多目标/主目标分配、自动配额、普通/绿窝、模拟摆位、多方案、拖动重评、锁定/替换、账号存档、缺口和分层迭代候选。单牌/无牌目标是同一奖牌集合规则的自然扩展，不另造算法。默认执行用户已确认的机会优先、同级优势集中、启用后可用合格母本换迭代覆盖、自选择优；迭代首版只提供下一步、原始值接近与遗传范围证据，不展开完整多代繁育路线。

后续再评估多代培养路线、实测产蛋效率、真实家园导入/障碍、异色炫彩收集路线和孵蛋结果记录。当前不需要机器学习、新图形引擎、通用求解依赖或复制蛋神的分数体系；基于有限窝位的兼容图与约束搜索即可先交付闭环。

## 7. 蛋神智能配窝设计评分（2026-10-16）

本节保留上轮评估原结论，不作为当前智能配窝的算法契约。其“先不推定后代奖牌”等建议，已由2026-10-17用户确认的宽容规划规则在本功能内更新；实际遗传概率仍未由该产品决策证明。

### 7.1 评分口径

评分依据是对蛋神助手本地 `planner-ui.js`、`planner-core.js` 及相关家园/配种模块的静态解包分析，结合本轮公开资料核对。分数评价的是“作为本地候选编排工具的产品设计”，不代表游戏内部遗传公式已经正确。满分10分，重点看用户能否理解、能否减少手工配窝、算法是否能稳定给出有用候选，以及结果是否能解释和修正。

### 7.2 总体评分

**综合：7.0/10。**

蛋神的强项是把“背包候选 → 账号隔离 → 蛋组/性别筛选 → 多窝组合 → 锁定替换”串成了一条可操作流程，适合作为日常选种公、选种母和规划窝位的助手。主要扣分来自策略名和权重不透明、部分目标使用跨账号统计、锁定个体可以绕过常规候选条件，以及结果恢复后存在重新挑选父本的可能。它更适合做候选编排和覆盖优化，遗传概率仍需要独立证据层。

### 7.3 分维度评分

| 维度 | 分数 | 评价 |
| --- | ---: | --- |
| 易用性 | 7/10 | 有自动公母配额、手动公本数量、锁定、替换、重算和刷新，能覆盖日常操作；但“全覆盖、补缺种公、补缺种母、仅100dB”等开关缺少直观解释，用户需要先理解培育目标和蛋组覆盖。 |
| 实用性 | 8/10 | 能把单个账号内的多个候选压缩为可执行窝位方案，尤其适合种公较少、母本较多或需要补蛋组的场景；当前仍依赖背包快照，不能独立证明窝位距离、母本是否已产蛋或游戏内最终配对成功。 |
| 算法有效性 | 7/10 | 支持多对多兼容、自动遍历公本数量、蛋组覆盖、缺口补齐和绿色/学院窝候选，实际比单纯按图鉴排序有效；固定权重是启发式，未直接优化真实产蛋数量、距离、等待时间或遗传目标。 |
| 游戏规则贴合度 | 6/10 | 性别、同账号、蛋组、性格和体型/声音标签已经进入候选规则；小窝实际距离、产蛋占用、普通窝与学院窝差异、后代遗传概率还没有全部接入实测证据。 |
| 可解释性 | 6/10 | 算法有优先级和分数来源，但权重、加分、扣分和策略开关之间的关系没有面向用户展开，用户看到“推荐”时不容易知道是为了补蛋组、补性别还是提高当前目标。 |
| 稳定性与可修正性 | 7/10 | 锁定、替换、保存版本、失效锁提示和备用组合都有利于持续调整；恢复计划时按排序重新选兼容父本可能改变原结果，锁定和重算边界需要更严格的结果快照。 |

### 7.4 已发现的设计风险

1. **目标和评分没有完全同域。** 当前缺口统计可能汇总多个账号，再用于某个账号的方案评分。这样会让某账号因为其他账号缺种公或缺种母而获得额外加分，用户难以理解，也会偏离“同账号候选”的核心约束。
2. **锁定个体的准入口径过宽。** 实现会让锁定个体绕过部分常规性格、体型/声音标签过滤。锁定应该保留用户选择，但页面必须明确显示“已锁定但资料不完整/不满足当前规则”，不能直接把它显示成正常可配。
3. **结果恢复不一定保持原组合。** 恢复计划或替换后，若只按缓存分数重新取排序第一的兼容父本，可能得到不同于原计划的父本。应保存实际选择的实例和规则版本，只有用户点击重算时才改变未锁定结果。
4. **策略名偏算法内部。** “覆盖更多蛋组”“补缺种公”“补缺种母”“仅100dB”没有展示“会牺牲什么”。例如增加覆盖可能减少同一目标链的重复产出，补缺公对雌性-only 物种没有实际收益。
5. **当前评分偏向组合覆盖。** 新蛋组、新链和缺口补齐的权重很高，但真实玩家有时更在意目标物种、目标性格、当前窝位距离和下一次可收蛋时间。目标优先级需要进入评分，而不是只作为结果后的人工筛选。

### 7.5 对 SpriteLens 的改造建议

按优先级建议这样吸收：

1. **先保留产品骨架。** 保留账号隔离、候选刷新、自动/手动公母数量、锁定、替换、备用方案和缺口提示，这些是蛋神最有实际价值的部分。
2. **把评分改成可解释目标。** 每个方案同时显示“覆盖蛋组、覆盖目标物种、满足性格、使用实例数、距离/产蛋状态、未知资料数”，分数只是排序结果，不作为唯一结论。
3. **按账号计算缺口。** 缺种公、缺种母和目标覆盖只在当前账号内统计；跨账号只做独立方案，不混入当前评分。
4. **锁定后做完整校验。** 锁定不应绕过规则，只能阻止自动替换；不满足条件时保留槽位并显示具体原因。
5. **先接入真实窝位，再做遗传预测。** 小窝不重叠、中心距离、母本产蛋占用和真实场景配对属于配窝规划的基础状态，应优先于性格、资质、体型和声音概率。
6. **遗传部分使用证据等级。** 性格 `30/30/40` 可作为社区估算，个体资质、特长、体型和声音先显示“待样本验证”，不要把二手攻略数字变成确定规则。

结论：蛋神智能配窝值得作为 SpriteLens 的交互参考和候选排序参考，整体可以吸收约七成设计；账号内规划、规则解释、锁定校验、结果稳定性和真实窝位状态需要按本项目边界重新实现。下一版实施应先完成“确定性配窝规划器”，再用真实生蛋记录建立后代遗传证据层。
