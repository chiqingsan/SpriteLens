# 附近精灵列表（C03）

状态：已实现观察版，现场完整性与坐标校准待验收。读者：用户、前端与采集维护者。本文维护使用、来源与实现边界；持续任务状态见 [路线图](ROADMAP.md)，协议生命周期见 [场景观察规格](SCENE_OBSERVATIONS.md)。

## 使用与范围

2026-10-24 中途接入：账号归属确认后，后续精灵增量直接重建观察集合；新移动请求建立场景与玩家参考位置，无需旧实体缓存或重新进场景。精灵服务器路径按时间插值，中断/直接设点覆盖路径；玩家中心仍为客户端目标，不能宣称服务器持续确认坐标。未重新下发的实体保持缺失。

2026-10-24 数据有效性规则更新（优先于下文历史恢复说明）：没有当前可用数据时列表与雷达保持空态。请求失败保留同周期已有结果并明确标注「可能已过期」，切号/切场景/观察周期变化后不保留旧结果；重启只复用场景上下文，不展示缓存实体或坐标；战斗结束不恢复战前快照，等待游戏新下发实体。进行中的同周期后台请求本身不代表数据已失效，不以反复清空制造闪动。未按实体年龄自动过期；静止实体未更新不等于已经离场，不凭时间猜测删除。服务器路径、中断与直接设点已接入；其它未知协议仍计入未解析。

侧栏「便捷工具 → 附近精灵」展示本次连接观察到的实体，包括名称、本地头像、属性、等级、身高、体重、音量原值、实体编号及更新时间。支持名称/配置/实体编号搜索、最近观察/名称排序与手动刷新。

只展示已观察范围，始终标明「不完整观察」，空列表不等于附近没有精灵。缺字段显示未知，未知配置保留配置编号、不借用其它物种。卡片会显示大块头/小不点、婉转声/粗嗓门及满重/底重、满分/底分等数值参考标记；同时命中体型和声音参考线时显示双牌标识。这里的标记来自当前物种范围和观察数值，不能替代游戏实际奖牌确认。米制距离和真实方位尚未校准，不展示为已验证结果。身高/体重采用参考实现与已有精灵展示的 `/100 m`、`/1000 kg` 约定。

切号、传送（包括同场景传送）、战斗边界、断线与停采集改变观察周期。战中不展示战斗前实体；战斗结束不恢复战前快照，等待游戏重新下发：真实日志回放（2026-10-24，11 个战斗窗口）显示结束后 120 秒内服务器重新下发 0–142 个实体，因此「清空 + 等待重发」可用。刷新失败保留同周期旧结果并明确提示，切周期后不保留旧结果。

## 状态所有者与失败分支

Python `SceneRepository` 是实体和 `uid/version/observation_id` 的唯一所有者；`observation_id` 随清空周期增长。`GET /api/nearby` 联查静态映射，沿用本机鉴权和受控 runner，不写数据库。现有单一 WS 只传上述版本摘要与 phase。正常停止采集时异步保存按「账号 + 抓包流」关联的场景上下文；格式 version=2 仅包含 uid、flow_id、scene_id、resource_id、instance_id、updated_at，不保存实体或位置。中途接入不要求收到 `0x014A` 才保存。旧 version=1 派生缓存直接弃用，不做迁移。重启后只有监控层确认同一流并注入 `resumed_identity` 才恢复上下文，阶段为 `resumed_stale`；收到新的有效实体增量或进场观察后转为 `observing`。切场景、战斗、新握手和连接关闭会清除对应基线；该缓存是可丢弃的派生数据，不代表离线期间的实时状态。

独立 Vue 页面持搜索、排序、请求和展示；应用壳仅挂载、卸载和转发摘要，不新增 WS、轮询或实体缓存。新周期/账号立即清空；响应按请求代次、uid、version 和 observation_id 核验，离页暂停并取消请求，实例保留；隐藏时仍接收周期失效，回页按最新摘要补取，忽略已取消的晚到响应。非法 DTO 明确报错；已更新的摘要不会被旧响应降级。头像失败显示本地状态图标，不自动请求外部资源。

## 左列表、右雷达与置顶悬浮窗（2026-10-23）

按用户本轮要求扩展为左侧信息列表、右侧场景雷达。列表与标记按字符串实体编号双向选中；从雷达选择目标时清除搜索并定位列表。桌面宽屏列表独立纵向滚动；窄屏将雷达放在列表上方，不挤成两列。

雷达复用解包实现的二维 x/y 相对坐标，玩家/移动目标参考位于中心；外环半径默认 10,000 原始坐标单位（`GET /api/nearby` 的 `radar_radius_raw` 下发，`config.json` 的 `nearby.radar_radius_raw` 可改），避免数据更新时缩放跳动。距离超过删除阈值（默认 15,000，`nearby.max_distance_raw` 可改）的实体从当前观察实体中清理；两者都按原始坐标单位，米制距离与真实方位仍未校准。默认值来自真实流量回放：玩家↔实体距离 p50≈7,990、p90≈8,881、p99≈8,994、max≈14,455，旧值 3,000 会删掉 85% 实体、旧半径 2,000 只画 8%。不把客户端移动目标当作服务器确认位置、不宣称真实地图方位。缺玩家位置时显示等待，缺实体坐标时只在列表保留；零值和负值保留。

雷达点按实体关注级别区分普通、重点和双牌三类，使用颜色、点大小和图例共同表达；颜色只作为辅助，不能把点色解释为已验证的游戏稀有度。悬浮雷达沿用同一分类和图例。

「悬浮雷达」通过桌面桥创建独立自绘工具窗口，可拖动、缩放、关闭；on_top=True，首次打开不请求焦点，同一主窗口仅允许一个实例，关闭可重新打开。它是非激活置顶工具窗口，游戏独占全屏、不同权限等级的游戏窗口覆盖仍未实机验证。

## 2026-10-24 数据口径与配置（原始单位、只读快照）

- **距离常量改为可配置的原始单位**：`scene_repository.DEFAULT_MAX_DISTANCE_RAW = 15000`（删除阈值）、`web/nearby.py DEFAULT_RADAR_RADIUS_RAW = 10000`（雷达半径）。配置键 `nearby.max_distance_raw`（默认 15000，[1000, 200000]）与 `nearby.radar_radius_raw`（默认 10000，[500, 200000]），写在 `config.json` 里，改完重启生效；不暴露 UI（设置页不新增字段）。阈值只影响内存过筛与绘制，不是协议事实。
- **读接口无副作用**：`SceneRepository.snapshot()` 只读，不再推进移动插值；推进改由写路径负责——逐包处理时按事件时间推进，服务端状态推送循环每次取数前调 `SceneRepository.advance()`。因此 `GET /api/nearby` 与 `/api/state` 重复读取得到相同的 `version`/位置，前端不会被自身轮询制造的重载驱动。
- **失败语义**：请求失败保留同周期数据并提示「可能已过期」；账号/场景/观察周期变化必须清空。与 [UI_GUIDE](UI_GUIDE.md) 的「数据更新不得造成 UI 闪动」一致。
- **切页保持与首屏**：附近页离开时只隐藏不卸载（复用壳的 `page-cached`），搜索、排序、选中与滚动位置保留；重新进入时若摘要同周期且有数据则原位更新不重载，若页面尚无数据则补一次加载。首屏不因切页重新出现「正在读取」。
- **悬浮雷达心跳与失效**：主窗口每 1 秒经 BroadcastChannel 广播 `ping`（页面隐藏/最小化时照常，仅推送连接断开期间暂停）；悬浮雷达 3 秒无任何消息即清空实体并显示「数据已失效（采集连接断开或主窗口未响应）」，恢复后自动重订阅并补拉快照。主窗口后台刷新失败时发 `stale`（有图时保留旧图并标注可能过期），无图时才发 `error` 清空。
- 回放证据与进一步差距见 [审阅快照](reviews/2026-10-24-nearby-review.md)。

- **视口工作台**：`#nearby-root` 占满内容区（flex 列、100% 高），列表与雷达各自内部滚动，整页不纵向滚动；1440×900、1920×1080、1280×800、864×672 均无页面滚动，640×720 单列时为页面内部滚动。顶部五段（大标题/状态条/工具条/计数/警告）压成三行，workspace 起点由 387px 降到 219px。
- **卡片密度**：78px 级（头像 48、标题行内联「名称 / Lv / 属性 / 标记」、内联「身高 · 体重 · 音量」、`#…末 9 位` + 相对时间），首屏 1440 为 7 张、864 为 5 张、1920 为 10 张；长名称 ellipsis + `title`，编号与时间可悬停读取全文。
- **分栏**：列表 : 雷达 = 1.15 : 0.85（雷达最小 300px）；≤900 单列且列表在前、雷达下移 340px；≤640 工具条换行、头像 40px。页面 `<h2>` 改为读屏专用，避免与顶栏重复。
- **雷达**：面板填充、三环刻度（10k/5k/2k 原始单位，按配置半径换算）、中心「你」、选中 + 最近 6 个名称标签（同名聚合 `×N`、越界翻转、半透明标签底）；compact（悬浮窗）保持隐藏刻度与普通标签，只显示选中标签与中心点。
- 本小节的卡片密度替代 C03 段落中「标记行固定 40px 并横向滚动」的旧描述。
