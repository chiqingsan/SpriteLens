# 精灵背包对标清单与迭代计划

更新：2026-10-12。对标蛋神助手电脑版 v1.1.6 解包前端，核对 SpriteLens 当前工作区代码及真实录制。第1轮真实箱浏览、箱号导航、三队视图已实现并验证，详见 [BACKPACK_BOX_VERIFICATION.md](BACKPACK_BOX_VERIFICATION.md)；后续轮次仍为计划。

## 目标与边界

完成背包内“找精灵 → 筛个体 → 看详情 → 回游戏定位 → 判断新增/整理”的完整流程。其它页面不进入本轮。

沿用三主题、即时筛选、点击/Enter 详情、Esc 返回；按用户决定不做悬浮放大。现有属性卡片、对比表格、等级/天赋/系别筛选继续保留。当前六组已保存条件不能因升级丢失。

蛋神的前端行为可核对；其后端数据准确性和由阈值生成的标签不能仅靠前端代码确认。完成状态指当前工作区代码；本轮背包演示界面已验收，用户运行中的旧进程需重启后加载新代码。

## 二、实施顺序与验收门槛

### 第 1 轮：把点阵背包变成真实游戏背包（最高优先级）

**状态：已交付核心范围。** 真实箱、三队、筛选固定槽位、导航、详情定位、未知入口、旧快照兼容、历史标记及键盘导航完成。真实样本与325项测试结果见验收报告；放生/库存删除仍归第4轮，不宣称已验证。

后续用户调整：删除独立位置未知入口和切换逻辑；确认30格全空的箱隐藏，保留实际箱号、零命中但有占用的箱与部分未采集箱。角色新增会话接续，详见 [SESSION_RESUME_VERIFICATION.md](SESSION_RESUME_VERIFICATION.md)。

**交付：** 真实箱 6×5 网格、空格/不匹配/未采集区分、箱号导航与命中数、详情定位跳转、位置未知入口、可核验的队伍视图。

- 后端：扩展已有箱位模块，保存完整箱表及覆盖状态，提供箱/槽/匹配数载荷。静态排序只影响检索卡片/表格，不改变固定槽位。
- 前端：点阵默认显示真实箱；工具条区分箱浏览与检索，切换保留选中；箱号超过一屏按批导航。容器窄时允许水平滚动以保持六列，字号不无限压缩。
- 队伍：先检查已有录制中的 PetTeamInfo/PetTeam；确定队伍索引、真实槽序与特殊队伍排除后接入。若样本不足，先交付仓库箱，不伪造 18 格位置。
- 未捕获箱表不能显示为空箱。持久化位置标为历史，当前登录后按新快照更新；箱数量/空箱从服务端证据产生，不硬编码 41。

**验收：** 觅觅蝠仍在第 2 箱第 1 行第 3 列；筛掉它后原格不被其它精灵填充；小帕尔移动只有一个位置；筛选命中箱数和详情一致；未知位置精灵仍可找到。验证登录、切号、交换、重启、空箱、未采集箱。

### 第 2 轮：对齐业务筛选与快捷语义

**交付：** 性别按钮、炫彩/异色、特性、奖牌多选与对应快捷项、单项快捷设置、分组清除、搜索补齐。

- 先接已有证据的炫彩和性别；与奖牌/特性名称和集合映射并行核对资料，不等待其它页面。
- 单项快捷点击只改变自己负责的字段：同组选择按该组语义合并，跨组取交集；再次点击撤销此项，不清空无关条件。
- 旧六组命名组合保留并迁移标识，点击明确为替换整组筛选；单项快捷数量按可用空间折叠，不借用六组的任意上限。
- 身高/体重实际值与范围位置都保留；100%/0%用真实值和精度判断，不用四舍五入后的文案判断。
- 奖牌集合待核验前仅提供“佩戴奖牌”筛选，不能把它叫作“全部奖牌”。无特性/无奖牌与未知分别处理。

**验收：** 任意三个快捷项可组合；改详细条件后快捷高亮同步；删标签、单组清除、总重置一致；重启保留快捷定义且不自动恢复业务筛选；新字段进入已保存组合契约；非法输入和鉴权测试通过。

### 第 3 轮：详情和识别信息补齐

**交付：** 统一卡片业务区域、真实图鉴编号/性别/形态、特性与奖牌图标、进化链、技能描述、当前属性/加成口径、显示设置补齐。

- 优先直接用现有静态数据；技能描述缺失 133 条显示暂无说明，不生成说明。
- 保留物种范围/蛋基础范围/个体实际值三种含义。范围位置提高显示精度，缺失/越界提示可见。
- 按当前同页背包条件查看同蛋组；详情返回保持箱号、筛选、滚动和选中。
- 稀有图标、奖牌是游戏业务资源；本地 SVG 用于操作按钮，来源和映射分别记录。

**验收：** 普通/炫彩/异色与不同性别样本显示一致；佩戴奖牌和奖牌集合不混淆；长名称/多奖牌/未知 ID 不挤压布局；技能说明与静态记录一致。

### 第 4 轮：实时可信度、获取方式与日期

**交付：** 字段存在性、局部更新合并、库存变更、更新时间/历史状态/待补全计数、获取方式和日期筛选、新增提示。

- 先核验局部简表不能覆盖已有详细字段：缺失不等于零或空集合，明确的零/清空仍必须生效。
- add_time/catch_way 先比对普通捕获、孵化/赠送等实际记录；未验证时间只保留原始数据，不命名为捕获日期。
- 捕获/移位/资料补齐/登录全量区分事件原因。新增只计确认的新事件，不把历史库恢复当新捕获；提示提供查看入口，不重排当前阅读位置。
- 准确描述缺失原因；箱位未知不自动代表个体资料不完整，静态范围缺失不要求用户反复登录。
- 检查当前 2000 只内存上限与实际容量；若触顶需明确提示或按证据调整，不能静默丢弃。

**验收：** 0 dB 与未知分别显示和筛选；简表后详细字段不丢；真实清空能更新；重复事件不重复新增；历史恢复/切号不误报；只收到局部快照不能判定其它个体已消失。

### 第 5 轮：背包整理与目标提醒

**交付：** 本地规则标记、按箱提示、清除标记；目标设置、已验证新捕获命中提醒及继续/停止监听。

- 整理规则复用已验证筛选，预览命中数与箱位；反选只作用于明确选定、数据充分的范围，不能把未知资料当成不合格。
- 标记按账号和 gid 关联，移动后跟随个体；本地标记不能执行游戏删除或回放客户端操作。
- 目标监听基于真实新增事件，资料分批到达时等待补齐、去重；切号重新建立基线。目标多规则为任一命中，单规则内条件同时满足。

**验收：** 标记可取消、不跨账号；缺资料不误标；登录整包不产生一堆目标命中；同一捕获事件只提醒一次，停止监听立即生效。

## 四、共同完成标准

- 每轮有独立可用结果和更新后的对标状态，避免只增加按钮而没有查询/持久化/未知行为。
- 数据、接口、偏好迁移和事件测试覆盖新增语义；全量测试、启动烟测、JS 语法及 diff 检查通过。
- 桌面验收 1440/1280/960/640px、三主题、离线/缺图/缺资料、多条件、推送和详情状态；记录截图与尚未通过项目。
- 高精度数值用于匹配，展示格式不改变结果；真实箱模式不受排序影响。
- Enter/Esc/Tab 可用；箱格方向键/焦点在刷新后稳定；切主题不丢箱号和筛选。
- 本轮计划没有引入悬浮放大、统一设置中心或其它工具页实施。
