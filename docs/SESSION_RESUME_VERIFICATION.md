# 会话接续与角色显示验证

2026-10-12。用户要求保存会话ID、密钥和账号，以便助手重启后接续原游戏连接。

## 原因与实施

当前问题的最新录制035435包含后续流量，却没有0x0102登录/0x0152进场景身份消息；前一段034311能够识别话绵雨、UID101384922、Lv55。原实现只恢复密钥和库存，未恢复连接到账号的关联。

- 捕获ACK密钥时，在本地密钥目录写入`session.json`版本1：flow_id、key_hex、identity（拿到身份后补齐）、server_sequence、updated_at。沿用latest.key兼容旧密钥功能。
- 只保存已确认的角色。会话ID使用现有抓包层的客户端IP:端口。key与flow关联；首次身份消息到达后补入UID/昵称/等级，每5秒最多刷新一次服务端序号，停止采集时保存最后序号。采用临时文件替换避免半写文件。
- 重启后缓存只是候选。只有同一flow、匹配密钥成功解密出合法服务端记录且序号高于检查点，才在PacketEvent附接续身份。复用现有身份、切号、账号落库和WebSocket推送路径，不伪造登录包或重置箱表。
- 客户端消息不确认角色；新SYN/ACK、FIN/RST关闭（现有close_session路径）、序号重置使旧身份关联失效。新真实身份优先，切号继续清旧账号快照。密钥变化、其它flow、坏文件不恢复旧身份。
- 密钥只写现有本地密钥目录，不传到UI/API，不输出明文到日志；ACK提取失败日志改为长度，避免打印候选密钥。旧latest.key空文件/非法长度降级为无密钥。
- 未确认接续时可显示缓存账号，但顶栏明确“上次角色 · 本次未确认”；收到真实身份或通过接续确认后自动切为“当前角色”。缓存账号不提供当前账号归属，不据此跨账号写入。

## 使用与边界

首次运行新版需要登录游戏一次，让新关联文件同时拿到密钥与账号。之后游戏连接未改变，重启助手并收到服务端流量即可确认接续。只有旧latest.key没有账号关联时，不能用最近账号猜当前账号，继续显示上次角色，直到重新进入游戏确认。

保存的是最近已确认会话，不能恢复未保存的其它并行连接或跨新连接序号重置。接续是同一连接的恢复；不会主动发游戏请求，也不重新执行已记录操作。若服务器改变序号规则，当前判断保守回落身份待确认。
