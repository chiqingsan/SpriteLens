# 野生精灵搜索覆盖记录规格

状态：2026-10-27 用户确认的产品目标与待实施规格，2026-10-29 按世界所有者分桶补充；不代表现有功能已完成。读者：用户、实现者、AI 协作者和复核者。维护边界：定义搜索覆盖的语义、算法和验收；当前实施状态见 [路线图 C13](ROADMAP.md#c13游戏底图与工具本地观察区域)，资源与协议证据见 [地图计划](NEARBY_MAP_PLAN_2026-10-26.md)。本文件中产品规则优先于地图计划中较早的“仅记录采样所在格”和“禁止按半径外扩”方案；当前运行行为以代码为准。

## 1. 目标与含义

用户沿地图寻找双牌野生精灵。地图应累计标出工具在有效采集期间预计已经覆盖过的区域，方便安排路线、减少重复走动。记录是本工具的搜索辅助，不读取或模拟游戏的解锁、迷雾或探索进度，不保存野生精灵为实时对象，也不意味着该区域中的双牌已经捕捉。

**记录格表达“该格至少有一部分落入过某次估计的下发范围”，不表达“格内每个位置都收到过数据”或“该区域精灵已经全部检查完”。** 范围是估计：实际服务器下发边界、采集丢包、延迟、遮挡、楼层、位置误差和精灵刷新都会影响结果。UI 可称“已记录范围 / 未记录”，必要时说明是估计覆盖；不能显示为已完全扫描、保证无双牌或游戏探索率。用户想减少重复搜索，不能靠夸大确定性实现。

**覆盖进度按「世界所有者」分开记录（2026-10-29 用户要求）。** 自己的世界与进入的每一位他人的世界各有一份独立进度：同一张地图上换了世界主人就换成另一份覆盖，不与自己世界的足迹混在一起；切回自己世界时恢复自己那一份。用户可手动清除进度，清除只作用于当前所在世界的那一份，其他世界不受影响。除自己世界外的进度从**开始记录**起只保留 3 天：满 3 天即自动清除，之后再进入该世界从头记录；继续记录不会延长保留期。

## 2. 范围、网格和几何规则

1. 在通过适用性校准的地图和楼层中使用固定世界坐标方格，分辨率不随地图缩放变化。现有边长 2,000 原始单位（大陆现场比例约 20 米）作为**待实机验收的候选值**，不是协议事实；坐标轴、格尺寸和版本一旦用于保存，必须随记录保存并稳定解释。
2. 每个合格的人物位置样本形成一个以该位置为中心的二维估计下发圆。**圆与方格有任何交集（包含只触及一角或边界相切），即把该格记为已记录**；不按覆盖面积比例、格子中心或精灵数量判断。所有样本的结果取集合并集，重复记录幂等。
3. 世界坐标使用向下取整定义格索引，包含负坐标；圆到方格矩形的最短距离不大于半径即相交。处理边界相切时，候选格遍历也须覆盖圆边界两侧，不能仅依赖不含相邻格的整数区间。地图外区域不画入或计入该地图；边界部分保留地图内合法格，不能把越界坐标夹到边缘伪造记录。
4. 只储存已记录格集合，不持续保存每个圆、图片蒙版或完整轨迹。渲染按需要从格集合派生；颜色、缩放和图像不是权威数据。位图、行区间或其他紧凑表示由实现者根据实测选择，需有稳定编码版本、边界和容量证据，不预设额外依赖。
5. 任意相交即整格涂色是用户明确选择的取舍：格边缘未受圆覆盖的部分也会被标记。20 米方格中，最远可能有接近一个格子对角线（约 28 米）的几何外扩，加上位置和半径误差；较小方格更准确但存储和渲染成本增加。**不得悄悄改成仅中心点相交、整格完全覆盖才记录或逐个圆永久存储。**

### 半径是待确认策略

**用户决定（2026-10-27）：** 先分析现有真实事件日志，再继续实现。当天 14:30–15:25 的场景 103 日志中，56 个首次进入精灵与 1 秒内客户端位置采样的平面距离中位约 86 米、p90 约 89 米、p95 约 91 米；123 个与移动目标的样本 p90 约 89 米，最大约 180 米。样本包含客户端历史位置及时间差，异常值可能来自延迟或位置误差，不能当作服务器保证的固定最大范围。用户要求继续完成，首版采用 **9,000 原始单位（约 90 米）的估计半径**，单独于雷达半径，UI 标明估计；后续更多地图或现场证据可能需要修订。用户同时决定：同一账号的同一地图合并记录，手动清除当前地图后开始新一轮；层/坐标体系仍须有证据才可合并。野生精灵刷新时既有记录的显示和逐格时间仍需进一步确认。

真实日志单场景样本的 840 次可解析距离，p90 约 8,881、p99 约 8,994、最大约 14,455 原始单位；这不是首次下发距离分布，参考位置可能是移动目标，最大值也可能包含移动或延迟移除。[证据](reviews/2026-10-24-nearby-review.md#21-距离阈值量纲错误--真实数据下列表几乎恒空)不足以证明服务器有固定圆形下发范围。大陆现场距离换算约 100 原始单位/米，二维覆盖仍不代表含高度差的三维距离。

用户要求“接近服务器下发的最大范围”，现有证据支持约 90 米的起始估计，但不足以确认最大值；14,455 或 180 米个例不能直接作为最大半径。后续应对不同地图、方位、移动速度和进出范围记录实体首次进入/离开数据，以已确认人物位置为参照。雷达显示半径、实体清理阈值和搜索覆盖半径是不同语义；调整雷达缩放不得悄然改变历史覆盖。记录必须能追溯生成时采用的半径与规则版本；半径改变后的历史不应在缺少原始轨迹时被重新计算或声称具备新精度。

## 3. 采样资格与连续移动

- 覆盖在后端有序事件链生成，页面关闭或切页不影响；一次样本必须有已确认的账号、连接、地图/楼层、有效位置和有效采集状态。客户端目标点不等于走到，不得对未来目标直接刷格。
- 进场与传送落点、客户端历史分段、停止位置分别保留来源和可信度；现有实现已接入，但历史分段是否确为过去位置及其时钟语义仍需真实游戏逐动作核对，不能把当前代码当成现场证明。战斗、切号、切场景、断连、停止或归属不明确时不新增覆盖；战斗结束、重连后需重新确认有效来源。
- 移动途中的样本可能稀疏。如果直接只画离散采样圆，快跑时圆之间会出现漏记；但直接连接目标点、跨传送或跨长时间缺口又会误记。仅当连续样本属于同一账号、连接、地图/楼层及连续运动段，且位置来源和时间/位移约束有实测依据，才可沿**已证实走过的路径段**补采或用线段扫掠圆计算等价网格。没有证据时只记合格样本圆并保留缺口，不猜路线；传送只记确认落点，绝不连接两端。
- 2026-10-28 用户确认保持未确认缺口，只降低显示延迟。附近页与打开中的悬浮雷达将后台合并间隔调整为 500 ms，与服务端推送节拍对齐；仅声音提醒时仍按 2 秒合并。只读分析最近三份本地事件分片，客户端历史样本的请求内时间差中位数约 547、p90 约 1798、最大约 2708（数值单位及位置语义仍待现场确认），前端提速不能消除样本本身晚到或缺失。
- 2026-10-28 现场证据与实现变更（修复「清除足迹后一段时间不出覆盖」「持续跑动不覆盖已走过区域」）：真实事件分片显示行走时客户端约 10 Hz 发 0x0133，`to_pos` 每 tick 只前进约 100~200 原始单位（p28 实测 p50=144，骑乘隐含速度 p50≈1,366、p99≈1,723 原始单位/秒；包内 speed 字段实测为空，不能作为判据）；停止包与历史分段很稀疏，旧实现只在停止/合格分段时记格，长跑时停止点间距超过 2×半径，导致沿途空洞且覆盖只在停下瞬间跳变。现在把**同一连续运动段内**的移动请求也当作走过位置的证据：仅当同一账号、连接、场景处于 observing、与上一条移动请求的请求时间差 ≤ 2,000 ms 且位移不超过 4,000 原始单位/秒×时差 + 400 容差时，才以 `to_pos` 记格；超出（传送、脱战回位、路线重算、丢包缺口）只更新参考位置、不记格也不连接两端，保留未确认缺口。清除足迹后从下一条合格移动请求起重新出格，不再等下一个停止点。回放 p20/p24/p26/p27/p28 真实分片，行走请求点所在格 100% 被覆盖，传送/长间隔处保留缺口；历史分段的时钟语义仍待现场核对。
- 记录范围应与有效接收观察的时段相关。仅有位置或网络连通不能证明每个实体已经下发；对接收是否就绪、下发延迟、游戏暂停及异常丢包的判定要先取证。不能通过空列表或静默推断该圆内已经完整检查。

## 4. 历史、刷新与归属

- 用户需要跨次搜索时仍能识别之前去过的地方，本地记录已实现持久保存与重启恢复。按用户选择，同账号同地图合并；楼层/坐标体系无法确认兼容时不得合并，游戏内多线或实例是否共享精灵仍未知，记录不能证明当前线路的精灵已检查。
- 野生精灵可能刷新、重生或更替。静态累计格只说明**曾经**估计覆盖，不能保证现在仍已检查。需要明确显示记录的时间范围或最近更新时间；是否每格记录最近覆盖时间、何时过期、何时开始新一轮搜索，以及自动过期还是手动重置，均待用户确认和实际刷新规律取证。不得自行定义刷新周期，也不能无提示永久把旧记录当作当前轮已检查。
- 停采/断连后可以只读展示已保存区域并标明记录时间或状态，但实时精灵和玩家位置的失效规则独立执行，不能恢复旧点或触发旧精灵提醒。战斗和同图传送不删除历史，切号/切图立即显示对应归属。手动清除须明确账号、地图、记录范围及生效结果，不得影响实时实体；超时不能假定成功或失败。
- 覆盖归属到「世界所有者」分桶：持久化键为「账号 + 世界所有者 + 地图」，世界所有者 0 表示自己的世界，其余为他人世界。旧版保存文件没有世界所有者字段时按自己的世界读入，不丢弃已有历史。手动清除只清当前世界所有者的当前地图，不影响其他世界；非自己世界的记录从开始记录时间起满 3 天后由后端在装载和运行时自动清除并重新记录，继续记录不延长保留期；清除失败不得假报成功，也不能影响自己世界的记录。
- 原 `MAX_CELLS=16384` 小于大陆候选约 204×204=41,616 个网格，现已提高到每地图 65,536 格；仍须在支持的地图和实际数据上核验容量、越界及多账号开销。容量不足或写入失败必须可见，不能静默停止记录。持久化必须保留未写数据、处理写入失败/退出和并发清除，使用项目既有事务与归属边界，不删除或覆盖用户已有历史。

## 5. 当前实现与未决事项

当前工作区 `SceneCoverage` 使用 2,000 单位格、9,000 原始单位估计半径、圆与格相交记录、行区间 DTO；只记录已校准支持地图内的合格采样，过滤越界方格。覆盖记录按账号、世界所有者和地图异步原子保存、重启恢复与手动清除；容量每地图 65,536 格，保存规则版本、半径及最近一次新增记录时间，写入异常可提示，半径不一致不会合并。2026-10-27 真实事件日志离线回放 6,571 条相关事件，临时记录大陆 334 格并成功重启读取，未写入用户业务数据。当前记录不含逐格时间；不同地图的真实范围、连续采样可靠性、采集代次归属与真实游戏动态验收仍未完成。

2026-10-29 已按世界所有者分桶：`0x039D ZoneScenePlayerVisitInfoSyncNotify` 的 field 1 `online_visit_owner` 作为当前世界所有者（0 表示自己的世界），`0x0152` 顶层 field 7 `online_visiting_owner` 与 `0x0160` 顶层 field 2 `sync_info` 的 field 14 `online_visit_owner` 作为次级同源字段；世界所有者变化时清空当前世界的显示并切到对应桶，`/api/nearby` 的覆盖 DTO 增加 `owner`、载荷增加 `world_owner`。该字段语义有真实事件日志对照：2026-10-29 16:49:40 用户退出拜访（发出 `0x02DE ZoneSceneExitVisitReq` 后）服务器推送 `0x039D` field 1 = 0，16:49:48 重新进入他人世界推送 `0x039D` field 1 = 369460069；全过程场景始终是同一张开放世界地图（`scene 103 / res 10003 / inst 1`），说明「他人世界」是在同一地图内分层，按所有者分桶正合需求。`0x0160` 只在人物全量同步时带同一字段，重新进入他人世界（16:49:48）时没有该包，因此不作为即时信号。仍未验证：其他进入路径（家园、组队/好友传送等）是否同样推送 `0x039D`，首包顺序与断线重连后的初始值需现场复核；3 天保留期从开始记录时间算（继续记录不延长），不区分玩家是否仍在同一世界。

仍需证据或用户决定：① 下发范围与其他地图/场景的关系；② 野生精灵刷新后历史是否按时间区分；③ 楼层及坐标体系能否安全合并；④ 是否需要逐格最近时间和对应的储存成本。搜索轮次采用用户选定的当前地图手动清除，同账号同地图合并。

## 6. 验收要求

- 几何回归：圆覆盖格角、相切、跨格/负坐标、格边界及地图边界、重复样本、重叠并集；圆覆盖每个角但不包含格中心也应记录。验证相切邻格不遗漏，并验证实际格集合而非只测试算法自身。
- 数据及生命周期：完整地图容量、多账号/地图/楼层隔离、采样时切号切图、战斗/传送/断连/重连、延迟或乱序样本、移动目标未到达、持续移动的间隙；未确认路径不能被填满。
- 持久化：保存、正常重启、切号恢复、重复写入、版本不兼容、磁盘失败、关闭/重试、清除与并发采样，以及半径/坐标版本变化；失败不假报成功、不污染其他账号。
- 性能和布局：完整地图、最长运行时间和多个账号地图的真实规模，记录内存/磁盘/更新耗时；连续更新不闪动、保留位置和焦点。正常与极限数据、最小窗口、窄屏及高 DPI 均需真实渲染目视验证。
- 真实游戏核对：静止、连续移动、取消远目标、障碍、传送、战斗、重连及双牌搜索；对照服务器事件和游戏画面验证采样与覆盖，并记录观察范围和刷新规律。缺现场证据时保留“待验收”，不能将估计区域称为精灵已全部查看。
- 世界所有者：同一地图内切换世界所有者后覆盖立即切到对应桶、切回自己的世界恢复原进度；双方手动清除互不影响；他人世界的记录从开始记录起满 3 天后自动清除并能重新记录；旧版保存文件可正常读入。真实游戏须核对进入/离开他人世界时 `online_visiting_owner` / `online_visit_owner` 的刷新时机与是否归零。
