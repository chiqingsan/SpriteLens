## 目标与布局分析

- 仅重绘家园内容区。左居民面板、右配对面板顶边/标题对齐，桌面宽度约 62:38；居民两列同高卡片。主面板背景暖白，细边框，弱阴影；不用多层嵌套框。
- 每张居民卡：左约 35% 原图立绘 + 下方产蛋胶囊；右姓名/性别/等级、性格/蛋组、身高/体重/声音。完整浅粉/浅蓝性别边线替代左侧粗线，绿色柔和立绘背景。资源 object-fit: contain，保留原图透明区域，不裁切/重绘/下载替换。
- 配对条目不单独套卡。母本一行、父本一行，父本标签只一次；首头像对齐，父本始终单行可按鼠标拖动，滚动条外观隐藏。产蛋一行；蛋重和分贝下一行。性格每项是“名称 + 独立概率条 + 百分比”，两列排列。
- 图上 11 位、6 个母本、精灵名和数值为示意；必须继续绑定真实载荷，不能写死。图上的场景时间戳无现有字段，不添加。

## 给 Luna6 的执行方式

使用 gpt-6-luna，高推理；按以下两个受约束的小任务顺序执行。第一批做完先报告，Codex 看差异后再发第二批。不自行追加抽象、组件拆分、后台字段或未要求交互。未知项只保留真实占位。

### 第一批：布局和居民卡

1. 读 AGENTS.md、docs/UI_GUIDE.md；检查 git status。检查上述参考图片和两个现有文件。
2. 桌面 .home-layout 改为约 1.6fr:1fr，右栏至少 340px；面板 padding 12-16px，gap 12px。标题用 --fs-xl，计数使用主题深绿。左面板计数简化为真实 N 位；排序提示可保留 title 说明或小字，避免挤压标题。
3. 保持居民网格两列；内容区宽度 <=1000px 时左右面板上下排，居民仍两列；<=620px 居民单列。不要当前 <=1150 就把居民强制一列。默认卡片最小宽度约 300-320px，min-height 216px，原图区域约 35%、最低 100px，其余为信息。同排等高，无额外标签时不塌陷。
4. 卡片用 --radius-lg 或由其局部组合的约 16px 圆角、整圈 2px 性别浅边线（color-mix 现有性别变量），底色只混少量性别色；不要重阴影、动画位移。图片背景用主题色的柔和渐变/低对比层次，不加外部图。选择/键盘焦点仍可见。
5. 名称主标题，性别徽章显示本地 UiIcon gender-female/gender-male + 雌/雄，等级保持浅绿胶囊。物种名与姓名相同则省略重复行；不同物种名保留小字。未知性别保留真实未知语义。
6. 性格和蛋组紧凑并排，蛋组用已有 --male 浅蓝体系区分；不要新增色值。身高用 ruler-2，体重 weight，声音 activity（本地 sprite 已有）。三行轻色背景、数值列对齐、轨道同宽，字体可读，单位不截断。产蛋胶囊保持图片下方。
7. 声音条仅用于 -100~100 dB 刻度的位置显示，ratio=clamp((voice+100)/200,0,1)，title 明示刻度；null 显示 — 与空轨道，不能伪装成 0dB。身高/体重沿用真实 pct，不改计算。禁止伪造声音概率。
8. 所有颜色用既有 CSS vars/color-mix；间距字号圆角走 tokens。只报告这两文件改动，不运行全套测试，不提交。

### 第二批：配对区

1. 保留每个母本独立条目；每个条目标题 + 场景记录，无图中假时间戳。与左面板标题基线、内边距对齐。条目间单条细线。
2. 母本和父本都为 标签(固定约3em) / 头像(32px) / 名称 的单行结构。标签至首头像、头像至名称都为同一 --space-2。父本 label 仅出现一次；父本之间 --space-5；现有 pointer capture 拖动和隐藏 scrollbar 保留。
3. 产蛋仍显示真实 egg 名称与图；蛋重/分贝移动到下一行的轻量横排，无盒子/竖粗分隔，窄时自然换行。保留未知占位和实际数值。
4. 每个性格概率项改成“名称 / 轨道 / 百分比”同一行；两项并排，余项下一行；独立 0-100% 进度，随机琥珀、未知灰色、其它主题绿。不能合成一根分段条，也不能改变 nature_prediction 分布。
5. 不删除现有 medals、选中详情入口、场景蛋等数据展示；图片不裁切，长名称不把其它栏挤出面板。保持错误/空状态和拖动保存失败提示。
6. 运行 .venv/Scripts/python.exe -B tools/frontend.py build；git diff --check。不要新增/运行镜像实现的测试或整套门禁。报告改动文件、构建结果和无法确认的目视问题。
