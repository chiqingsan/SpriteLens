# 2026-10-15 侧栏切页延迟诊断

状态：已定位，尚未修改生产代码。读者：维护者与实现者。本文保存本轮合成 demo 的代码与计时证据；不替代真实 WebView2 性能剖析，后续代码变化需重测。

用户确认问题发生在左侧页面导航。本轮保留工作区原有改动，仅在本目录新增诊断脚本及记录。

后续修复与复测见 [FIX_VERIFICATION.md](FIX_VERIFICATION.md)；本文保留修复前快照。

## 结论

切页的共同等待感首先来自整页 280 ms 淡入；图鉴还有重复销毁/重建、批量 DOM 渲染的实际主线程停顿。每次导航无条件请求目标页，又增加了重复构造、传输、校验和提交的工作量。本机合成数据的请求并非全部页面的主要瓶颈，不能据此归因于 Python 语言性能。

1. `spritelens/web/static/app.css:11,104-105` 将所有 `.page.active` 设为 280 ms 的 opacity 0→1 和 translateY 淡入。导航本身不等接口才切换，但页面先透明再出现，形成拖拍。动画不等于主线程阻塞；它与请求、布局并行，耗时不能相加。
2. `spritelens/web/static/app.js:794-812` 的蛋图鉴 leave 会卸载 Vue 应用；load 清空根节点，再 mount。`EggDexPage.vue:49,64-68` 每次挂载都会请求，加载期间用占位替换内容，然后一次渲染全部卡片。本轮共 224 张。首次进入有 59、281 ms 长任务；返回仍重建，有 69、99 ms 长任务。具体长任务中 JS、样式、布局与图片工作的各自占比尚未获取浏览器 trace，不能把全部时间归给某个组件。
3. `app.js:130-162` 每次导航都执行目标页 load，没有依据账号/版本和已加载状态跳过重复工作。宠物页即使已有 bootstrap 快照、账号和版本未变，切回仍重新拉取 `/api/pets`。`usePets.ts:42-66` 仅省略同版本 options，仍解析并提交整个列表；`app.js:352-359` 又等 load 结束才恢复滚动位置和选中详情。原生精灵图鉴请求后重写 120 张卡片的 innerHTML。
4. `app.js:239-245` 返回概览时只用 total，却请求完整 `/api/pets`。本轮该请求返回并解析约 94 ms，是不必要的数据处理。概览已有 bootstrap 和 WS 更新途径。

## 运行证据

使用项目真实本地服务、已发布 Vue 运行包，合成 2000 只宠物、8 枚蛋；浏览器为 Codex 内置 Chromium。诊断脚本只在独立服务返回的 HTML 内注入，没有改动运行静态文件。脚本用 capture click、fetch/JSON 包装、两次 requestAnimationFrame、PerformanceObserver longtask、animationend 记录时间。

下表摘自 [measurements.json](measurements.json)。请求含响应体读取/JSON；长任务属于对应切换时间段，并未进一步拆分。动画结束时间含首次样式更新与主线程调度延迟，故可能大于 CSS 280 ms。

| 页面 | 请求开始至 JSON 完成 | 主线程长任务 | 点击至淡入结束 |
| --- | --- | --- | --- |
| 精灵背包首次 | 90.7 ms | 55 ms | 343.2 ms |
| 精灵背包返回 | 111.1 ms | 未观察到 ≥50 ms | 309.5 ms |
| 精灵蛋仓首次 | 28.2 ms | 90 ms | 303.5 ms |
| 精灵蛋仓返回 | 76.4 ms | 未观察到 ≥50 ms | 317.1 ms |
| 蛋蛋图鉴首次 | 19.7 ms | 59、281 ms | 409.1 ms |
| 蛋蛋图鉴返回 | 15.0 ms | 69、99 ms | 322.5 ms |
| 精灵图鉴首次 | 38.9 ms | 71 ms | 303.0 ms |
| 概览返回 | 94.3 ms | 未观察到 ≥50 ms | 309.0 ms |

各次点击的同步 handler 只有约 0.3–0.8 ms；首个 rAF 在约 3.7–55.8 ms 出现。用户感觉的“切换慢”同时包括动画未完成、数据重取和部分页面真实掉帧，不是导航 handler 本身执行了几百毫秒。未将两帧采样称为精确首绘或完整可交互时间。

## 建议修复顺序

1. 移除页面切换的整页透明度/位移动画，保留按钮等局部反馈，先消除共同的 280 ms 拖拍。
2. 蛋图鉴保留挂载和已加载内容；离页只暂停/失效请求与详情交互，返回先展示旧内容。首次卡片渲染加数量上限或复用现有虚拟列表能力，以重测结果选最小方案。不要仅保留数据缓存却仍反复卸载和重建 224 张卡片。
3. 同账号、同版本、同筛选的背包/蛋仓返回直接使用已有状态；版本变化或失败重试再拉取。保留切号、请求取消、旧响应失效与草稿保存约束，不跨账号复用缓存。滚动/详情恢复不应绑定到无条件全量请求完成。
4. 概览使用已存在的统计状态更新，取消只为 total 拉完整列表。原生图鉴缓存命中时保留现有 DOM，内容变化才重绘。

修复后按同一路径比较冷/热切换，重点看 ≥50 ms 长任务、请求次数、内容连续性以及切号/离页乱序保护；不恢复整套浏览器门禁。本轮只诊断，没有运行与该问题无关的全套测试，也没有新增语言或依赖。

## 复现脚本与边界

运行 `.venv/Scripts/python.exe -B output/tab-latency-20261015/probe_server.py`，打开其打印的本机 URL，依次进入背包、蛋仓、蛋蛋图鉴、概览、蛋蛋图鉴、精灵图鉴、背包、蛋仓。在 DOM 的 `#tab-probe` 中可读取 JSONL。在本目录创建 `stop` 文件可使诊断服务正常释放资源退出；再次运行前删除该标记。

没有连接真实账号、录制或密钥，也没有操作真实抓包。浏览器页内未出现控制台 error。以上是一次代表性样本，不是 p95；尚未在用户当前 WebView2 进程里测量，也未覆盖所有侧栏页面。绝对时延会随设备、图片缓存和数据规模变化。
